# Action V1 兼容退役说明

## 行为变化

BKLog 与 BKMonitor 不再支持 IAM V3 内的旧 Action V1 兼容。这里的 Action
V1/V2 是产品动作模型迭代，不是 IAM V3/V4 协议版本；IAM V3 仍然受支持。

- 删除 `IAM_V1_COMPATIBLE` 的读取、缓存与写入。数据库中遗留记录不自动删除，
  无论缺失、`true` 或 `false` 均不再影响鉴权，也不再产生该开关的数据库查询。
- 当前 Action 策略使用 SDK 的标准查询，不再去掉 `_v2` 后缀追加旧动作查询，
  不再做 `space → biz` 请求转换、`biz → space` 旧策略转换或 V1/V2 策略 OR 合并。
- 保留 SDK 必需的协议接口，当前 Action ID（包括没有 `_v2` 后缀的现行动作）、
  资源路径、缓存隔离和异常契约不变。监控 `new_dashboard` 的管理动作别名仍保留，
  它是产品语义，不是 Action V1 迁移兼容。
- 删除两平台一次性的 `iam_upgrade_action_v2` 命令。BKLog `migrate_grafana`
  保留配置迁移和统计，只删除原本没有执行的权限迁移代码及其导入；原有命令参数保持兼容。
- BKLog V3 模型同步只处理当前 `initial.json`，不再根据旧开关同步 `legacy.json`。
  保留历史模型文件以及监控已有迁移链与执行记录；不重放已完成迁移，不删除远端模型或授权。

## 升级前检查与恢复

本版本要求环境已完成 Action V1 → V2 权限迁移。若仍存在仅有旧 Action V1 授权的
环境，升级后这些旧授权不再参与产品鉴权；显式设置 `IAM_V1_COMPATIBLE=true`
也不能恢复。请先完成权限迁移并验证当前 Action 的权限，再升级。

发布时更新所有 Web/API/Worker 进程，避免滚动期间新旧版本鉴权语义不同。
本改动不更改 IAM 模式、创建者授权、申请入口或上层业务 API；不执行存量权限迁移。
若发现遗漏的旧授权依赖，应暂停升级并回退到此前软件版本，结合旧版配置恢复行为，
再完成权限迁移。回退不等于权限数据回滚，本改动没有删除原配置或远端权限数据。

## 验证边界

离线回归验证当前 SDK 单条/批量策略请求、允许/拒绝、异常传播、资源范围、缓存及
仪表盘管理动作别名；模型同步用 mock 检查只执行当前模型。真实 IAM、各部署环境
的存量授权完整性与滚动发布效果不由离线测试证明，需在发布前确认。
