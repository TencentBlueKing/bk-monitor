# Architectural Patterns

覆盖 15 个模式：

- Layered Architecture
- Clean Architecture
- Hexagonal Architecture
- Onion Architecture
- Feature-Sliced Architecture
- Modular Monolith
- Micro Frontend
- Plugin Architecture
- Event-Driven Architecture
- Pipe and Filter
- MVC
- MVP
- MVVM
- Flux
- Unidirectional Data Flow

## Rules

ARCH-001
Architecture MUST be selected based on system constraints.

ARCH-002
Architecture MUST NOT be confused with a design pattern.

ARCH-003
Architecture defines large-scale dependency and responsibility boundaries.

ARCH-004
Architecture MUST NOT be selected only because it is popular.

ARCH-005
Micro Frontend MUST NOT be introduced without organizational or deployment boundaries.

ARCH-006
Clean Architecture MUST NOT become unnecessary abstraction.

ARCH-007
Feature boundaries SHOULD follow business capabilities when business complexity is high.

ARCH-008
UI components MUST NOT become the primary location of business rules.

ARCH-009
Dependency direction MUST be explicit.

ARCH-010
Architecture MUST optimize for changeability rather than directory aesthetics.
