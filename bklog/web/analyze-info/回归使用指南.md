# V3 功能与 UI 回归基准使用指南

本目录是后续新增功能、调整功能及修复组件库差异的复查入口。当前版本为 `ui-alignment-20261112-r1`，属于**部分参考基准**，不是全业务验收通过证明。业务、视觉及发布验收分别记录，不能互相代替。

## 先执行快速回归

所有命令从 `bklog/web` 执行，不需要浏览器或登录，不连接真实写接口。

```sh
# 核对证据摘要和源码变化；此命令不执行产品用例
node analyze-info/harness/run-regression-baseline.mjs --verify

# 列出已登记组、用例数及补充浏览器验证入口
node analyze-info/harness/run-regression-baseline.mjs --list

# 执行全部已登记的 63 条快速回归
node analyze-info/harness/run-regression-baseline.mjs --all

# 按改动文件选组；多文件重复 --changed，不读取 Git 暂存区、不自动提交
node analyze-info/harness/run-regression-baseline.mjs --changed packages/web-v3/src/shared/global/overlay/use-dialog-visible.ts

# 基准工具本身的反例验证
node --test analyze-info/harness/tests/regression-baseline.test.mjs
```

`--changed` 接受 web 相对路径、`bklog/web/` 开头的仓库相对路径、web 内的绝对路径。删除文件也可作为变更输入。公共兼容层、样式、测试辅助函数及已登记依赖配置变更触发所有组。映射是显式规则，**不是完整依赖图**：调用方改动、动态组件、构建配置等未登记路径会返回 `UNMAPPED_CHANGES`，退出码 2；需要补充影响分析与用例后再验收，不能忽略该文件。

每次运行生成独立 `runs/regression/*.json`，保留原输出、用例计数、Node 版本、工具与证据摘要、V3 参考文件及原冻结 V2 图中的源码摘要、运行中变化和参考失效文件。退出码 1 表示工具、证据或测试失败，0 只表示对应命令在登记范围内成功。`--verify` 或 `--list` 的 0 不能当作执行了 63 条测试。

源码变化会列入 `staleReferenceFiles`，意味着相关参考需重验，不等于产品失败。源码回归通过时仍输出 `businessAccepted:false`、`visualAccepted:false`、`uiReviewRequired:true`。缺少、重复、额外、跳过、TODO 或空测试不能判通过；单纯进程退出码 0 也不够。

## 已登记的四组快速回归

- `related-controls`：15 条。上下文/实时日志共用的筛选、高亮、字段设置：完整词组粘贴、trim、去重、上限、颜色保持、删除、字段顺序模型、草稿、取消、最少保留一项及提交参数。
- `overlay-state`：20 条。弹层注册、层级、父子关闭、初始可见、原生 Dialog 与相关日志弹窗状态。Registry 改动还会选中收藏组。
- `favorites`：21 条。收藏管理及侧栏的既有源码行为回归。覆盖测试中的状态、事件和请求 spy，不代表真实收藏写入已验收。
- `reactive-data`：7 条。响应式数据克隆、隔离与原数据保护；登记了字段设置、设置表格、用户选择、集群和采集调用方。

精确文件路径、每个用例名字及影响规则以 `baselines/ui-alignment/2026-11-12-r1/manifest.json` 为准。历史 `context-native-20261112.json` 有 72 次通过记录，其中完整 Registry 入口导入了基础入口，16 条被重复执行，独立用例为 56 条。本基准只保留完整入口，再加 7 条克隆用例，共 63 条。保留历史文件原样，不将重复执行计入新增功能覆盖。

22 处按钮主题修复仅有源码对照与非主题 AST 一致性证据；其余 2 个主题候选、27 项未证明对应关系、Vue 模板和其他未扫描目录仍待检查。它们不属于上述 63 条完整页面验收范围，修改这些页面时须另建契约，不能把快速回归全绿当作已经覆盖。

## UI 对齐执行顺序

1. 先读取 V2 对应组件、样式、事件、store 和请求，再核对 V3 实现。记录操作、事件名、model 的 prop/update 事件、插槽参数、返回值、校验、错误和取消处理。不要按组件名称直接推断等价关系。
本段具体业务环境与运行记录已移至仓库外本地归档；复验须提供本地授权测试上下文。
3. 固定中文、Asia/Shanghai、浏览器版本、字体、缩放、1440×900 主视口和 1280×800 补充视口；使用相同绝对时间和相同脱敏响应。动态数据的两次截图不能作为像素等价证明。
4. 先验证操作及请求效果，再采集默认、加载、空、错误、无权限、展开、悬停、焦点、禁用和弹层状态。控件尺寸、文字、图标、对齐、边框、颜色、滚动分别登记。
5. 每个弹层单独截图：Dialog/Drawer 正文、标题、footer、关闭区、内部滚动，以及挂到 body 的 Select/Tooltip/Popover。不要只截主页面，或只检查 scoped 样式是否存在。检查 Teleport 后的实际节点、主题类、层级、遮挡、滚动与定位。
6. 验证嵌套层打开后能实际点击；Escape 先关子层再关父层，关闭后焦点及资源清理符合源码。不得只看到 DOM 存在就记为可操作。
7. 保存配对截图、差异图、操作步骤、视口、响应摘要、源码版本、控制台错误和断言结果；只遮蔽明确的动态内容，不能遮蔽缺失控件或业务结果。

上下文现有参考尺寸：筛选下拉 72×32、独立 checkbox 16×18、前后行输入 48×26、ERROR 标签约 71.336×22、关联标题分隔 1×14。原始 V2 实测视口是 1728×817；V3 补验过 1440×900 和 1280×800，**尚无两个固定视口的同数据配对像素基线**。这些尺寸用于定位回归，不构成全页面视觉通过。

特别复查：原生 Dialog 默认层级曾高于子 Tippy，导致字段弹层出现但无法点击；当前应由 Registry 分配父子层级。字段弹层真实根为 `.tippy-box[data-theme~="field-config-popover"]`。标题内原通用分隔类曾被外层样式撑到整行，现使用 `origin-log-title-*` 专用类。

尚未证明通过的重点：真实拖拽重排、标签间左右键及插入、字段持久化成功/失败、权限/取消、实时日志本批真实复查、其他路由及所有嵌套弹层。不得由源码 model 测试代替拖拽手势，也不得用上下文替代实时日志验收。

## 新功能与调整后的基准维护

1. 从 V2 来源或明确的新需求写下契约，使用 `baselines/ui-alignment/case-template.json` 登记源码依据、入口、状态、断言和证据，不自行补充业务规则。
2. 为变更增加有区分力的逻辑、事件、异步及取消断言；登记 requiredCases 和影响规则。共享组件改动回归所有已验收调用方，不能只运行新页面。
3. 先跑快速回归和工具反例，再按 UI 顺序完成真实浏览器验证。新增未登记功能应保持 `UNMAPPED`，而不是放宽规则让它通过。
4. 新建日期/版本目录，保留旧版本。人工复核源码、证据摘要和用例名单后，在 runner 的 manifest 入口切换版本。没有“自动接受当前截图/全部通过”的开关。
5. 记录业务、视觉、发布三个独立结论；待验证和阻塞必须带缺失证据及重跑条件。全局严格类型检查仍有历史错误，应记录实际输出并处理新增诊断，不能因局部测试通过宣布类型检查通过。

写入验证只操作本次创建的专用资源，记录标识、创建步骤、允许操作及清理方式；不编辑、删除已有业务资源。快速回归中的 spy 不能充当真实新增、启停、删除验收。
