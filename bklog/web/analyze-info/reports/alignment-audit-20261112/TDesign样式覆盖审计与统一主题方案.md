# TDesign 样式覆盖审计与统一主题方案

实施进展：公共主题基础见实施记录 27；13 个业务模块的样式源码覆盖、语义值收拢、重复契约及验证门禁见[实施记录 28](实施记录-28-全模块主题覆盖收拢.md)。下文原始审计事实保留，不以源码治理结果替代完整视觉验收。

## 结论与边界

可以收拢为公共方案，但不能通过一套全局 Theme 替代全部组件覆盖。建议以语义主题统一视觉基础，以组件变体统一重复的 V2 外观契约，以公共业务控件统一交互，以局部样式表达业务布局。避免将现有散落规则直接拼接成更大的全局覆盖文件。

本次为分析及方案整理，未修改运行时样式、组件行为、V2 或依赖版本。静态审计不代表浏览器视觉验收，也不据此宣称可删除某个比例的 CSS。

## 审计方法与实际范围

- 调用 TDesign MCP 的 vue-next 文档和 DOM 工具，检查 ConfigProvider、Form、Drawer、Select、Table。
- MCP 当前没有独立的主题查询工具；主题变量可用性补充核对本地已安装 TDesign 1.20.10 的类型及 70 个 CSS 文件，不能把服务返回的文档当作当前安装版本的完整兼容保证。
- 扫描 V3 src 下全部 SCSS，以及 Vue 文件的 style 块；去除注释后提取 `.t-*` 类名和 `--td-*` 声明。输出只有源码路径、类名、计数和变量名，无运行数据。
- 133 个 SCSS 文件包含类名引用，共 650 次文本引用；这些文件合计有 169 个 `!important`。169 是整份匹配文件内的数量，不全是 TDesign 覆盖。
- 另外 57 个 Vue 文件的 style 块包含类名引用。190 是两种文件数量之和，不是覆盖规则或可删除规则的数量。
- 词法扫描不展开 Sass 嵌套、不证明选择器可达、不计算优先级、不判断懒加载顺序；不扫描 TS/JS 内嵌样式、模板内联 style、第三方包内部样式或最终构建 CSS。上述部分在实际实施前补充检查。
- 同时保留 .t-input、.t-select-option 等独立类族，不把状态类当作组件种数。不能把统计解读为业务组件数量。

复验命令：在 packages/web-v3 目录运行 `node tools/audit-tdesign-styles.mjs`。同目录的 tdesign-style-inventory.json 保存本批源码清单；它是工程元数据，不包含业务证据。

## 各模块覆盖分布及处理方向

以下数字为包含类名引用的 SCSS 文件数；完整文件和类名见清单。

- 检索 48：按钮、输入、字段选择、聚类规则及弹层较多。收拢标准控件颜色和尺寸；查询条件双栏、字段列表、聚类表格自定义过滤、上下文分栏保持业务契约，不能作为通用 Table/Drawer 默认样式推广。
- 采集 36：表格、表单、校验输入、标签选择、步骤及集群较多。优先整理管理表单和嵌入单元格两种控件变体。采集表格与其他管理表格密度不同，不能同用一个强制行高。
- 归档 6：抽屉 Form 控件宽度、表单项间距、分页操作可共用管理规范；仓库卡片、ES 源行和恢复进度的组合布局保留。
- 脱敏 6：Input 内层、Checkbox/Radio 标签、按钮等覆盖较多，且存在 important。拆分嵌入编辑控件与普通表单；编辑器背景和字段规则布局不改成全局输入框主题。
- 提取 5：基础操作按钮、表单和列表归入管理变体，路径选择和任务详情等专用布局保留。
- 客户端日志 5：标准按钮统一主题，任务工具栏与日志详情的暗色局部区域保留局部语义主题，避免随全局普通表面色改变。
- 清洗 3：详情侧栏及模板表单采用公共 Drawer/Form 配置；清洗字段表及调试区使用单独变体。
- 偏好设置 2：普通按钮和标签字号可共享；偏好布局、设置弹窗组合保持局部。
- 集群管理 2：es-slider 的 Form、Tag 和输入布局归入侧栏表单变体；容量和连接配置仍是业务内容。
- Grok 2：抽屉表单与操作区适合共用管理 Drawer；代码输入、调试与模式提示保持局部。
- 授权 2：统一按钮视觉；无权限页和授权列表的布局保留。
- 索引集 2：统一标准按钮、表单控件及弹层；关联资源、拖动等状态保持业务实现。
- shared/ui 7、shared/styles 4、shared/global 2、app/shell 1：这些本来就是公共层。首先明确其所有权，避免新增主题后与既有主题、骨架、兼容抽屉、管理列表和全局空间选择继续竞争。
- 不在此清单中的目录不代表无需治理：可能只使用公共组件、Vue style、内联样式或未出现 `.t-*` 字面量。

## 现有公共基础和问题

### 已有资产应复用

- shared/styles/theme/tdesign-bklog.scss：332 行，混合主题声明、层级、默认按钮、Dialog/Drawer 页脚、下拉选项和 display 适配。
- shared/styles/theme/compat-drawer.scss：兼容 Drawer 头部 52px、内容 padding、操作按钮尺寸。
- shared/styles/theme/management-lists.scss：普通管理列表的表头、行、分页和操作按钮契约，明确排除采集专用表格。
- platform/compat/tdesign/legacy-control-styles.ts：引入原生组件库 CSS 和公共兼容抽屉。
- platform/i18n/locale-provider.ts：已使用 ConfigProvider，当前主要注入语言。采集 TableComponent 内也有局部 ConfigProvider。
- 主应用 start.js 与 monitor-bootstrap.ts 都引入同一个 tdesign-bklog.scss：公共修改会同时影响主应用和 APM/Trace。

### 需要先修正的机制问题

1. **部分覆盖未命中原生 DOM。** tdesign-bklog.scss 中 `.t-button--size-medium` 在本地安装包按钮 CSS 中不存在；原生小/大按钮使用 `.t-size-s`、`.t-size-l`，普通尺寸没有该 medium 类。该结论针对库原生组件，不等于证明所有业务自定义类均无效。实施时以 DOM/组件源码验证后删除失效规则。
2. **尺寸映射并非一一对应。** 当前设置 s=26、m=32、l=38；按钮小号实际读取 xs、大号读取 xl，下拉选项读取 s。根变量本身合法，也不能保证所有旧尺寸契约都已实现。
3. **主题合法不等于主题充分。** 当前主题文件共声明 45 个不同的 TDesign 变量，70 个已安装 CSS 中均有引用；但仍缺完整状态映射与密度规范。例如成功/警告/错误仅修改部分基础色时，hover/active/light 等可能继续使用库默认色。
4. **主题与结构混在同一文件。** Dialog 页脚反向顺序、按钮间距、下拉选项内边距、业务 field-name 等不是品牌主题；应迁至明确的公共变体或组件。不能依赖全局覆盖抵消错误的 props/slot 映射。
5. **同一控件有合理差异。** 普通按钮 14px、表格操作 12px、普通输入 32px、过滤表格嵌入控件 41px、下拉骨架行 24px，均有不同场景。强制统一一个 height/font-size 会造成回归。
6. **局部已有明确业务例外。** report-log-slider 的深色正文、repository-slider 的固定宽度组合、cluster-mode-switch-confirm 的按钮顺序与宽度，不能无条件升级成所有 Drawer/Form/Popconfirm 的默认值。
7. **Teleport 和嵌入边界未显式解决。** 给应用根元素加 class 不会覆盖挂在 body 的弹层；只覆盖 :root 又会改变同页其他 SDK/宿主 TDesign 控件。主题边界必须覆盖弹层并兼顾宿主。
8. **暗色主题不是完整契约。** theme-dark.scss 当前主要提供暗色 Tippy；公共 Token 使用 :root:not([theme-mode='dark'])。没有证据支持当前全部硬编码业务颜色随 dark 模式正确切换，需作为独立验证项。

## 统一方案：四层职责

### 第一层：语义 Theme

在 shared/styles/theme 内维护唯一的语义 Token 来源，再映射到 TDesign：品牌及状态色、正文/次要/占位/禁用文字、页面/表面/悬停背景、边框、字体、圆角和阴影。复用现有 theme.scss 色值，不再维护互相独立的同义值。

建议将 tdesign-bklog.scss 保留为唯一入口，拆出 tokens.scss 和 tdesign-tokens.scss；首批保持视觉数值不变，避免在结构收拢时顺便改设计。

Token 示例：--bklog-color-action、--bklog-color-text-secondary、--bklog-color-surface、--bklog-color-border、--bklog-control-height、--bklog-option-height、--bklog-table-row-height。此处是命名建议，不表示所有业务 Token 都有对应的 TDesign 原生 Token。

对照已安装 CSS 的实际读取关系映射。--td-font-body-medium 是字体简写，底层字体大小和行高会传导到多个组件；不要为单个按钮直接更改全局 body-medium 字体来补偿。

### 第二层：有限组件变体

基础 Token 无法表达的共性放在 components/ 下，每类控件只有一处原生 DOM 适配。采用显式业务变体标记，不依赖任意祖先页面名：

- Button：普通操作、表格文字操作、图标操作。
- Form/Input/Select：普通管理表单、侧栏表单、表格单元格嵌入、查询编辑器输入。
- Table/Pagination：普通管理列表、采集列表、聚类结果；后两种不套普通列表统一行高。
- Drawer/Dialog：标准表单、详情、全屏日志/代码；统一标题/关闭/页脚间距，内容区可以明确选择有或无 padding。
- Popup/Select：普通选项、紧凑建议、Checkbox 多选；32px 选项和 24px 骨架不能混为一个全局高度。

优先通过局部 --bklog-* 驱动公共规则；确实由原生 --td-* 读取时，尽量把变量挂在具体原生部件上。将 --td-comp-paddingLR-l 直接挂在整个 Drawer 上，会连带改变后代按钮和输入；不能把它当成 Drawer 专属参数。

允许公共组件适配内部 .t-*，但必须绑定安装版本和测试。禁止在各页面再次复制同一组内部节点规则。

### 第三层：配置及公共交互控件

扩展现有 Provider，组合语言与经过核对的全局默认配置，而不是新建第二套独立 Provider。MCP 和当前 d.ts 均支持 Form requiredMarkPosition、Drawer 部分默认行为、Table size/hideSortTips 等，但 ConfigProvider 不是任意组件 CSS/props 的全局注入器。

- 只设置全应用明确一致的默认值；具体页面显式 props 优先。
- 行高、宽度、margin、popup 偏移不伪装成 ConfigProvider 配置。
- 公共 Drawer 负责主题标记、样式变体、关闭/未保存检查与层级接入；不要用 CSS 改变已有保存/关闭副作用。
- 公共过滤弹层负责可见状态、outside、Escape、焦点、确定/取消草稿；Theme 只负责视觉。
- 公共表格继续保留专用 columns、slots、排序和过滤协议，不用 TDesign 默认过滤菜单替代 V2 定制交互。
- Loading 沿用已有统一骨架管理；初次加载、分段追加和刷新状态不是 Theme 能完成的状态管理。
- 不为每个基础组件再造同名兼容库，不扩张旧 bk-* API。仅对重复业务契约增加明确的小封装。

### 第四层：局部业务布局

保留查询面板双栏、字段拖动、上下文/实时分屏、集群容量表、Windows Event 选项编排、Grok 编辑器、仓库卡片等布局。可以把颜色/尺寸引用改为语义 Token，但不把业务布局搬进全局主题。

## 主题边界及构建约定

1. 为主应用和每个嵌入实例明确主题拥有者。独立主应用可设置 document 主题；嵌入应用默认仅影响自己的根与弹层根，不修改宿主 :root。
2. 为 Teleport 提供受控弹层宿主或显式 popupClassName/overlayClassName/drawerClassName，保证主题变量在实际挂载处继承。选择哪一种需验证定位、滚动容器、遮挡和嵌套弹层，不直接全量更改 attach。
3. SDK 弹层单独验证。第三方包复用同页 TDesign 时也会继承根变量，不能认为“不改 SDK 源码”就不会影响它。
4. 暗色区域采用局部语义主题；如暗色 JSON 详情不等同整个应用 dark 模式。
5. 统一加载顺序：库基础样式 → 语义及 TDesign 映射 → 公共组件变体 → 业务布局。懒加载仍可能后注入 CSS，不能只依赖入口导入顺序；使用稳定命名和明确优先级约定。
6. 不把 @layer 当成自动修复：未放入 layer 的旧 CSS 默认会优先于分层规则。若采用 layer，需要同时规划原生库、兼容层和业务层，否则先不引入。

## 分批实施方案及退出条件

### P0：固定当前事实

- 保留本次清单，补充 TS 内联/动态样式扫描与实际最终 CSS/DOM 审计。
- 为每条候选规则记录来源、变体、状态、V2 依据、是否受 Teleport 影响及替代去向。
- 先标注失效/重复/冲突，未经 DOM 验证不删。
- 合成夹具覆盖基础控件和侧栏；实际业务证据仅保存在仓库外。
- 退出：试点控件有完整状态契约及可重现基线。此时才形成可删除规则列表，不预估缩减百分比。

### P1：语义 Token 与 Provider

- 拆分公共入口职责，保留旧入口确保主应用/APM/Trace 使用同源主题。
- 补齐状态映射，核对字号及按钮 xs/xl 映射，修正 medium 失效选择器。
- 明确主题及弹层边界；审查采集局部 Provider 与应用 Provider 的合并行为。
- 退出：普通/小/大按钮、输入、禁用、错误、hover/focus/active 和暗色局部区域通过；业务 CSS 暂不批量移除。

### P2：管理 Drawer/Form 试点

- 选择 Grok、归档仓库、ES 配置以及上报日志详情作为不同变体。
- 将重复标题高度、关闭占位、页脚尺寸和表单间距收拢；保留仓库卡片和深色 JSON 内容。
- 逐处替换为公共变体，同批删除已证明被替代的覆盖，防止新旧双写。
- 退出：宽窄视口、长标签、校验信息、内容滚动、固定页脚、复制、outside/Escape/取消和未保存保护均通过。

### P3：Table/Pagination

- 复用 management-lists.scss 现有契约，先普通管理列表，再采集、最后聚类。
- 共用排序/筛选图标视觉，不改已有过滤和排序业务；分别保留各表格密度。
- 退出：专用单元格、展开行、分页、筛选弹层、空/错/加载、固定列及长内容通过；不可只测默认数据态。

### P4：Input/Select/Popup

- 先普通表单，再查询建议和嵌入单元格；统一匹配父宽、hover/selected 和 loading/结果连续切换。
- 测试键盘、焦点、输入法、outside、异步竞态、Teleport、建议结果滚动及骨架行。
- 退出：不再使用局部 !important 补偿同一基础外观，保留经说明的业务例外。

### P5：其余模块与治理

- 按清单覆盖脱敏、提取、客户端、索引集、授权和偏好；同步处理 Vue style，不能只清 SCSS。
- 新增样式门禁：先警告新增业务 .t-* 内部选择器、硬编码视觉值和 important；人工批准的业务例外需写明理由及场景。不可直接禁止所有局部布局。
- 对每批维护“已迁入公共层/保留业务层/待验证”状态及删除前后规则差异。
- 主应用/APM/Trace 分别构建并运行嵌入验证；同页 SDK、多个弹层、懒加载后主题、部署和主题切换回归。
- 最终退出：每条移除规则有对应公共契约和验证去向，所有高影响差异修复，完整功能验收不能由静态清单替代。

## 验证准则与风险

固定视口、缩放、字体和合成数据；核对默认、hover、focus、active、selected、disabled、loading、empty、error 和展开状态。自动测试验证事件/状态；浏览器验证真实 DOM、尺寸与交互；截图只在仓库外。

不承诺“消灭全部 .t-*”。目标是重复的基础外观不再散落，业务差异有清晰所有者，公共变化可按变体回归。最大风险是把不同 V2 契约错误合并，造成聚类筛选、采集嵌入输入或 SDK 外观再次丢失；因此每批最多处理一个控件族，验收后才清理旧规则。
