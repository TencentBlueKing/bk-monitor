# 实施记录 06：采集搜索首次聚焦与输入顺序

本段具体业务环境与运行记录已移至仓库外本地归档；复验须提供本地授权测试上下文。

## 根因与修复

本段具体业务环境与运行记录已移至仓库外本地归档；复验须提供本地授权测试上下文。

首次点击顺序为 focus → 组件打开字段菜单 → 同一次 click 到达 TDesign Popup → Popup 按点击触发器语义反向关闭。修复前 DOM 的 contenteditable 已是 activeElement，但组件 is-focus 状态消失，菜单被关闭，用户需要第二次点击。

本批只改搜索组件：

- `handleVisibleChange` 接收 Popup 的触发来源；来自搜索区域自身 `trigger-element-click` 的关闭提议不再反向关闭已打开的字段菜单。真实外部点击、Escape 等来源继续关闭，保留外部点击事件和草稿处理规则。
- 输入区域空白/上下边缘点击显式聚焦 contenteditable，避免 Popup 看似聚焦但键盘未落入编辑器。
- 增加 blur 同步真实焦点状态。清空或完成查询已关闭 Popup 后，Popup 不再报告外部关闭，也能消除残留焦点样式；blur 本身不提交或清空草稿。
- 选字段后 updateInput 替换 contenteditable 文本会保留旧光标位置；原实现只 focus，实际可能把输入插到字段前缀之前。本批仅在选字段后的 nextTick 把选区折叠到前缀末尾，不干预普通输入和手动移动光标。
- 自身关闭标识只忽略没有触发来源的内部回调；不能吞掉后续真正的外部关闭。

保留字段数据、条件、子菜单、推荐值、多选、远程加载、键盘操作、change/input/update 事件、搜索回车参数与采集列表 reloadList。没有改后端协议、权限或已有资源内容。

## 浏览器验证

实际视口 1280×720。两版首次单击相同位置后：activeElement 均为可编辑输入、is-focus 存在、字段菜单可见，见 `first-focus.json`、`v2-first-focus.png`、`v3-first-focus.png`。

V3 进一步验证：

1. 输入区上下边缘单击同样聚焦；重复点击仍保持焦点及菜单。
2. 选择“采集名”，输入仓库外本地用例指定的测试值，Enter 后应保留完整条件。
3. 查询与清空后检查列表响应和恢复行为；具体资源及结果记录仅保存在仓库外。
4. 点击输入区外部，实际焦点离开、is-focus 取消、菜单隐藏。

证据：`v3-search-result.png`、`search-result.json`、`browser-results.json`。操作仅查询和本地筛选，不执行新增、编辑、删除。该结论限本批搜索链路，不代表全业务或全视觉验收通过。
