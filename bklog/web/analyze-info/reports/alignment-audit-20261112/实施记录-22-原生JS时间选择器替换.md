# 原生 JS 时间选择器替换

## 安装包依据

使用精确版本 `@blueking/date-picker-js@0.0.1`。依据安装包 README、dist/index.d.ts、core/types.d.ts 和实际实现完成接入。新包为原生 JavaScript 实现，仅依赖 Day.js，不需要 Vue 或组件库。

V3 package.json 和独立锁文件移除旧 `@blueking/date-picker` 直接依赖，增加新包精确版本。第三方 log-web 的封版依赖与本次范围不同，不擅自改动。V2 源码、依赖配置和 APM/Trace 旧发布目录均未修改。

## 接入及功能保留

`src/platform/sdk/date-picker/native-entry.ts` 保留业务已有的挂载、update、handleShowPanel、handleHidePanel 和 destroy 契约，内部改用 createDatePicker、on、update、show、hide 和 destroy。

- 保留两项范围值、normal/simplicity、时区、时区入口开关、格式和最大跨度配置，继续启用格式切换。
- 传入及更新时复制范围数组，避免 SDK 修改业务状态；不补造查询值或改变后端请求协议。
- 格式和时区为新包的受控选项，必须在事件中显式 update 回写，再调用原业务事件。
- 保留 TimeRange 原来的范围缓存、SEARCH_DEFAULT_TIME、SEARCH_DEFAULT_TIME_FORMAT、时区更新、批量缓存清理及 change/format/timezone 事件链。
- 保留组件 deactivated 时关闭面板、卸载时销毁实例；取消订阅仅执行一次，销毁后的公开方法不继续操作已销毁实例。
- 新包内置的最近/未来/自然日期、基准时间、双月日历、时刻输入与滑块、常用/最近使用、范围校验、格式和时区选择由官方实现承载，没有另写简化版本。

原组件未启用智能解析，本次也不自行加入 AI 请求或改变既有业务入口。README 中新包不支持的 Vue 插槽、bkui 属性透传不在当前 TimeRange 的使用契约中。

## 删除不再需要的隔离构建

新包无需 Vue runtime，因此主应用与 Monitor 均直接引用 SDK 边界。删除旧日期组件专用的 esbuild Vue3 island 插件、虚拟模块声明及 Vite 注册；类型和 CSS 改用新包。

更新第三方依赖边界审计：禁止 V3 源码重新直接导入旧日期包；只允许 SDK 边界、类型契约和时间组件样式引用新包。保留其他第三方组件仍需使用的兼容边界。

## UTC 回归与依赖锁定

浏览器测试发现原锁定 Day.js 1.11.10 在本地非 UTC 环境下，对零偏移时区的 tz(zone, true) 和 startOf(day) 存在显示及日历草稿偏移。仅校验时间戳会漏掉问题；必须同时校验墙上时间、日历输入和重新打开后的范围。

最终使用 pnpm 的定向 override：`@blueking/date-picker-js@0.0.1>dayjs = 1.11.23`，满足新包声明的兼容范围。主应用其他 Day.js 调用仍使用 1.11.10。未修改 node_modules、共享 Day.js 原型或日期 SDK 原型，也没有在业务中手工增加/减去时区偏移。

依赖安装后需重启 Dev 服务，清除模块解析缓存，再验证浏览器；只刷新页面可能继续执行旧依赖路径。
