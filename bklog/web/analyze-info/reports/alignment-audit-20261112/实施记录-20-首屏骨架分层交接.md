# 首屏骨架分层交接：分析与实施方案

## 现状研究

- HTML `src/index.html` 的首屏覆盖层包含空白深色导航和正文占位。`app/bootstrap/shell-gate.ts` 通过 DOM 删除移除覆盖层。
- 检索路由把正文就绪与顶部菜单结束绑定；workspace 又等待字段、检索请求、结果 DOM 和趋势图全部结束才通知路由。模块已初始化仍被整页层遮住，慢结果或渐进趋势会拖住整页。
- HTML、路由、workspace 分别设置兜底定时器。它们既不能证明模块已挂载，也会在正常慢请求期间强行放开视觉层。
- 已有 loading-queue 管理 page/trend 遮挡优先级，但未区分模块初始化与业务数据请求。现有原生 Loading 适配和局部骨架应继续复用，不改变请求、权限及数据状态。
- 导航的菜单、空间及用户有不同的就绪依据，不能因其中一个慢而覆盖整个正文，也不能把默认菜单当成最终信息。

## 统一解决方案

1. 保留现有 shell-gate 作为首屏唯一交接入口：HTML 正文、HTML 导航、检索正文初始化分别有明确释放责任。导航就绪不再是检索正文释放条件。
2. 正文整体骨架在必要索引初始化完成、真实模块及模块内骨架经过 Vue DOM 提交后释放；字段、日志、趋势结果不参与整体释放。模块内部继续使用原有请求 loading，互不等待。
3. 头部挂载后把 HTML 导航占位交接给导航区域骨架；菜单按菜单请求 settled、空间按空间列表 settled、用户按用户初始化 settled 分别退出。失败也必须进入可用错误/空态，不能永远骨架。
4. 删除正常流程中的固定秒数兜底。组件卸载释放其登记；延迟回调不得影响新路由。V1/无权限分支需要独立挂载交接，不能依赖 V3 workspace 的通知。
5. 增加共享骨架视觉生命周期：pending 结束立即释放逻辑遮挡，同时真实内容照常渲染；骨架只在视觉层淡出约 180ms。新 pending 到来取消旧退出，不让旧定时器删掉新骨架；卸载清理；减少动画偏好直接退出。
6. 不延迟 API，不等待动画结束再设置数据，不动画化业务内容 opacity，不把视觉退出状态当成请求状态。整体到局部交接时先显示局部骨架，再淡出整体覆盖层。

## 实施顺序和验证

- 先实现共享视觉生命周期及 shell-gate，添加幂等释放、重复加载、卸载清理、独立导航与正文测试。
- 解除路由/workspace 对结果和菜单的整页依赖；保留必要初始化；处理 V1、无权限、切换路由及嵌入入口。
- 接入导航区域骨架及 HTML 导航占位，接入通用模块 Loading 和趋势/管理骨架的统一淡出规则。
- 使用完全手写合成夹具验证：慢导航+快正文、快导航+慢结果、首次单次请求、分段趋势、失败、卸载、新请求打断退出、减少动画偏好。真实页面只读检查，任何原始证据只存仓库外。
- 执行相关测试、全量回归、主应用/APM/Trace 构建及源码索引检查，逐项记录实际结果及未覆盖状态。不能将源码实现直接标记为真实页面全状态验收。

本文件先记录分析和拟实施方案，完成后补充实际变更、验证结果及限制。不包含业务参数、接口数据或截图。

## 实施结果（2026-11-13）

- `app/bootstrap/shell-gate.ts` 统一 HTML 导航与正文交接，互不等待。菜单 settled 订阅可注销；HTML 只消融覆盖层，不淡出 `#app`。导航挂载后交接到内部区域，保留原高度以避免正文跳动。
- `app/router/retrieve.ts` 不再等待菜单或固定秒数；workspace 在必要索引初始化完成、下一次 DOM 提交后通知释放 page 队列。路由卸载与旧异步回调有失效保护。V1、空间无权限和组件加载失败有独立交接；非检索路由由 App 在 DOM 提交后释放遗留 HTML 正文。
- workspace 移除对字段、日志结果 DOM、趋势结束的整页等待和 10 秒兜底；启动层移除 12 秒兜底和“骨架释放后忽略菜单响应”的判断。菜单响应晚到仍更新真实导航。
- 停止将日志结果和趋势面板的旧 ready 标记作为整页释放条件。Pinia/监控兼容入口中的两个旧字段、方法及更新副作用暂保留并标记 deprecated，避免未经核验地改变外部协议；它们不再决定首屏释放。
- 导航的 HTML 占位增加实际骨架条；内部菜单、当前空间标签及用户区独立显示占位。当前空间已有初始化信息时立即显示标签，全量空间列表请求只影响下拉，不延迟已可用标签；失败/完成同样结束加载。
- `shared/ui/loading/presence.ts` 集中视觉退出生命周期、180ms 消融、减少动画偏好、取消和卸载清理；`presence.scss` 只设置覆盖层透明度，不作用于业务内容透明度。
- 原生 Loading 组件、指令/命令式实例、趋势首段骨架、趋势异步占位及日志首屏行骨架接入共享退出。真实内容照常提交，日志行骨架退出时改为覆盖定位，避免在真实结果下面额外占高。趋势分段请求仍保留首段后右上角进度，不重新覆盖已绘制图表。
- 指令在新请求到来前立即销毁前一退出实例并取消定时回调；卸载也立即销毁，避免旧 TDesign hide 清理新实例的父级定位。每次退出只作用于自己拥有的节点。

请求与数据状态仍由各业务模块拥有，统一的是初始化交接和骨架视觉寿命；没有把所有 API 聚合成一个大 loading，也没有延迟请求、结果赋值或等待动画才渲染。

## 验证结果

新增 `tests/first-render-skeleton-native.test.mjs`，涵盖退出时序、新请求打断、卸载清理、减少动画偏好、HTML 导航/正文独立释放、订阅注销及初始化不依赖结果。趋势原有测试继续验证单次与渐进请求语义；只调整其视觉 hook 依赖注入及 class 匹配方式，没有降低请求阶段断言。

纯合成入口 `/__fixtures__/first-render-contract` 不初始化业务服务：

1. 导航和结果均未结束时点击 Initialize modules，整体骨架退出，模块骨架与导航骨架继续保留。
2. 点击 Resolve results，在 Vue 下一次提交中捕获到 `leaving=true`，结果文本已更新、内容 opacity=1；证明动画只消融覆盖层，没有延迟数据渲染。
3. Resolve navigation 后导航区域独立退出；Retry results 只重新显示模块骨架。

真实检索页只读复验：实际视口 1728×817，观察到 HTML 正文和整页骨架退出，导航与结果区域正常渲染；当前空间区域的加载独立完成，最终导航骨架清零，页面无新增横向溢出。此检查未保存业务数据或截图，不代表所有权限、失败、网络速度和嵌入状态均已实测。
