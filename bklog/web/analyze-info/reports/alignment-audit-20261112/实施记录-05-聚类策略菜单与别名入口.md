## 2. 批量编辑别名点击无响应

V2 事件链：全局设置链接 → `show-index-config-slider` → SubBar 权限/类型判断 → `RetrieveHelper.setAliasConfigOpen(true)` → FieldAlias 的 `ALIAS_CONFIG_OPEN` 监听 → 原草稿抽屉。V3 链路前半段仍在，但 FieldAlias 被放在 TDesign Popup 的懒加载 content 插槽中。首次全局点击时没有挂载接收者，事件被丢弃；只检查 emit 存在无法发现这种生命周期差异。

修复：

- `src/features/retrieval/workbench/field-filter-comp/update/field-setting.vue`：将唯一 FieldAlias 实例放在菜单 content 之外，保留同一 `isFieldSettingShow` 条件；菜单内保留原文字/图标触发器，经 ref 调用同一编辑器。外部事件、字段菜单两条入口共用一个实例。
- 同目录 `field-alias.vue`：增加默认 true 的 showTrigger 展示属性，菜单外拥有者设置 false，只隐藏重复触发文字，保留抽屉及完整事件监听。没有修改字段元数据、对象字段展开、校验、保存参数、确认、取消或加载流程。

浏览器验证：刷新后直接处于 clustering，未点开字段菜单，从“全局设置 → 前往批量编辑别名”首次即可打开；DOM 只有一个 alias host 和一个抽屉；取消关闭，没有保存或修改已有字段。证据 `v3-global-alias-drawer.png`、`browser-results.json`。记录包含本次 HMR 曾出现的循环依赖报错历史；重新加载后验证最新代码，不将历史日志假称为零错误。
