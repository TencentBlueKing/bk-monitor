# 日期选择器 0.0.2 升级

本记录更新实施记录 22 中的版本和临时依赖锁定结论，历史验证记录保留。

## 包内依据与落地

- 安装精确版本 `@blueking/date-picker-js@0.0.2`，核对安装包 README、CHANGELOG、package.json 及现有接口。
- README 和依赖声明确认 SDK 自身固定 Day.js `1.11.23`，修复非 UTC 本地时区下的 UTC 显示及日历回填偏移。CHANGELOG 将该条列在 Unreleased 中，因此发布版本以已安装 package.json 和锁文件为准。
- V3 package.json 与 pnpm-lock.yaml 已无旧 `@blueking/date-picker-js@0.0.1>dayjs` 定向 override；新包实际解析到 `1.11.23`，主应用直接依赖仍为 `1.11.10`。
- 公开接口及受控格式/时区语义不变，保留现有原生 JS SDK 边界及 TimeRange 的缓存、查询事件、格式和时区联动，没有重写日期算法或修改 node_modules。
- V2 源码、依赖配置及旧 APM/Trace 发布目录保持不变。构建在仓库外独立目录执行，未覆盖旧发布产物。

## 验证结果

- 日期专用测试通过：范围值复制、配置透传、受控回写、显隐、事件订阅、重复销毁及无 Vue/UI 库依赖的 SDK 图。
- 扩展真实 SDK 回归：分别在上海、纽约本地时区，针对冬季和夏季日期，验证 UTC、伦敦、上海、纽约目标时区的时间戳、墙上时间、日历日边界、时刻设置及三轮回填一致性，全部通过。
- 浏览器合成验证通过：两种显示模式、常用范围、UTC 双月日历及绝对时刻提交、重新打开回填、格式选择、时区搜索/回写、外部关闭、宿主更新及实例销毁。
- 真实主应用新日期组件挂载、面板打开及关闭通过，无 Vite 错误遮罩；没有在真实业务上提交查询或写入配置。
- 主应用、APM、Trace 生产构建通过。两个 Monitor 产物均通过八项公开导出、样式资产、worker 和源码摘要校验；不等于所有外部宿主发布环境验收通过。
- 主应用实际模块图：旧日期组件和日期 Vue3 island 均为零，新 SDK 正常进入产物，原始 bkui-vue/bk-magic-vue 模块为零。
- 全量测试 448 项，442 通过、6 项为既有失败；扩展后的日期回归再次单独执行通过。严格类型仍有 1566 条既有错误，排除路径及行号变化后无新增诊断。
- 封版 V1 静态交付校验通过，runtimeAccepted 仍为 false，不将静态校验替代运行验收。diff 空白检查通过。
