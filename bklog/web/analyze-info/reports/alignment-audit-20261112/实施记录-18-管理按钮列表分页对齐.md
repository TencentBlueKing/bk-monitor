# 管理按钮、列表和分页对齐

本批只处理 V3 的展示和组件样式映射。V2 是源码及渲染基准；没有提交配置或操作已有资源。本记录不包含业务参数、记录、响应、截图或凭据。

## 根因及修复边界

1. 公共主题仍使用 `.t-button--size-medium`，当前安装版本的默认中号按钮没有这个类。管理页通过限定作用域恢复普通按钮 14px 字号、矩形按钮最小宽度；小号、大号、文字和图标按钮保留各自尺寸。表格操作文字仍为 12px/22px，不扩大为工具栏按钮。
2. Grok 搜索宽度仍绑定旧 `.bk-input-text`，原生输入包装层未命中。补充 `.t-input__wrap`，恢复 480px 宽度及父容器限制。
3. 普通管理表格使用 TDesign 默认单元格留白和中号操作按钮，行高增至 57px。给兼容表格增加明确标记，恢复 V2 普通表头和单行结果 43px、两侧 15px 留白、文字颜色及外边框。`outerBorder=false` 保留无外边框语义；多行内容允许自然增高。
4. TDesign 分页的总数 `flex:1` 将条数选择推到右边。恢复总数、条数选择居左，页码居右；页码 32px、间隔 4px、选中白底蓝框；底栏 15px 留白、63px 高及灰底顶边框。
5. 清洗模板导入/导出未指定 theme，触发 TDesign 主色默认值。显式设为 default，恢复次级按钮。保留其原事件、导入状态及导出弹窗。
6. 提取任务原本有独立表格设计，单独保留 42px 行高、16px 横向留白和灰色表头，不能套用普通列表的全部参数。

新增 `shared/styles/theme/management-lists.scss`，由管理布局加载。`manage-ui-aligned` 通过路由元信息及路径排除日志采集。普通表格依赖 `bklog-legacy-table` 标记；原生 ES 列表单独接入；清洗模板复用的采集式 TableComponent 不套用普通表格密度和分页规则。外部订阅 iframe 内部样式不由主应用接管。

## 源码依据

- V2 安装版本的 `bk-magic-vue/lib/ui/table.css`、`pagination.css`：行高、留白、分页位置及选中态。
- V2 `views/manage-v2/grok-manage`、`log-clean/clean-template/list.tsx`、`log-extract/extract-task/task-list/index.scss`：页面专属设计及按钮等级。
- V3 `platform/compat/tdesign/legacy-bk-controls.tsx`：增加表格标记及 outerBorder 支持；数据、列、分页、过滤及行事件协议不变。
- V3 `features/management/manage/index.vue`、`features/grok/current/index.scss`、`features/cleaning/current/clean-template/list.tsx`、`features/extraction/current/extract-task/task-list/index.scss`：作用域与页面例外。

## 浏览器验证结果

使用同一标签页切换两版，主对照视口实际为 1440×900。仅保留工程尺寸：

- Grok：新建由 56×32px/12px 字号恢复为 V2 的 64×32px/14px；搜索由约 167px 恢复 480px；表头和单行结果均为 43px；分页由下移至约 1357px 恢复至约 1075px，与 V2 同位置。页码样式和条数选择位置已修复。
- 清洗列表：43px 表头及结果行，操作按钮恢复 12px；页面无横向溢出。
- 清洗模板：导入/导出均为 64×32px 白底描边。专用表头 37px、结果行 65px 保持两版一致。复核实际单元格与内层表头文字均为 12px，因此不按外层继承字体错误扩大字号。分页仍保留采集式浅蓝选中态。
- 提取任务：表头 43px、结果行 42px，分页 63px，与 V2 专属密度一致。
- 归档仓库、归档策略、归档回溯、提取配置：实际页面的表头 43px、分页 63px；新建按钮保持页面原有 120×32px。当前样本的空态已检查，无页面横向溢出；空态不能替代有结果、展开或异常状态验收。
- ES 集群：实际页面可加载，原生表格接入专门作用域；本批样本只有空态，结果态、长列和筛选弹层仍待验证。
- 日志采集：没有 `manage-ui-aligned` 及兼容表格标记，原有结果行 65px 保持不变。
- 订阅管理：实际承载外部 iframe，没有本地 Table；不声明 iframe 内部列表通过本批验收。

## 可重复验证

开发环境打开 `/__fixtures__/management-loading-contract`，该入口完全使用手写合成数据，不初始化真实业务接口。

1. 初始为骨架覆盖；切换数据、关闭加载后显示结果，原表格持续挂载。
2. 初始每页五条，点第二页，首行为合成第六条；切换每页十条，原生分页保留第二页并显示剩余两条。验证分页渲染及数据没有被样式层替换。
3. 切换宽度，在实际 1280×800 下宽表约 1216px，页面无横向溢出；表头/单行 43px、底栏 63px。
4. 回归日志采集，确认作用域仍排除；新增页面或改动路由后必须重验这一条。
5. 有数据页面另验操作按钮正常/禁用/悬停、分页首末页、每页条数、长文本和多行；外边框关闭、展开行及固定列不能只通过默认截图判断。

## 剩余差异与验收限制

- 原生分页将“条/页”放在选择框内，V2 在框外；总数字符串间距也略有不同。这两项保留为待对齐，未标记视觉完全通过。
- ES 结果态、归档多行/展开、全部筛选弹层、独立索引管理/客户端/数据链路等没有逐状态浏览器验收；共享样式覆盖不等于这些模块全部验收通过。
- 本批未重新执行完整严格类型检查和 APM/Trace 构建；未改状态、服务和外部嵌入协议。
- 本批结论是已修复并验证上述展示差异，不能据此宣称全业务或全状态 UI 验收完成。
