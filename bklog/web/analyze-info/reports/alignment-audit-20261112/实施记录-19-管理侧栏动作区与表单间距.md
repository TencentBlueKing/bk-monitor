# 管理侧栏动作区与表单间距

本批继续对照 V2 源码和同一浏览器标签页中的实际渲染，重点修复归档新增侧栏。未修改 V2、未提交业务配置，未将截图、接口数据或业务参数写入仓库。

## 原因与实现

1. 管理页 `manage-ui-aligned` 位于路由内容上，传送到 body 的侧栏不是它的后代。上一批管理按钮的字号和尺寸规则不能覆盖侧栏。改在明确的兼容 Drawer 与原生 ES Drawer 作用域内设置中号按钮字体 14px、矩形普通按钮最小宽度 64px；不扩大图标、文字和小号按钮。
2. 动作区仍使用 V2 的 `mr10`，V3 缺少对应样式，提交与取消贴在一起。仅在上述 Drawer 中恢复明确带 `mr10` 的按钮右边距 10px，不对所有相邻按钮强制增加间距。
3. TDesign 表单项默认下边距 24px，与页面自己的上边距叠加，导致表单和按钮区下移。归档策略、仓库、回溯和 ES 表单分别移除多余下边距；各页原有上边距单独保留。
4. V2 归档策略相邻表单项为 8px，归档回溯为 18px，归档仓库普通项为 12px、集群项为 16px。这些差异来自 V2 库规则与页面规则的组合，不能只机械复制某一行 SCSS，更不能统一成一个值。按源码及实际测量逐页恢复。
5. `BkFormItem` 的 `ext-cls` 没有转为原生 FormItem 的 class，导致仓库的集群横向行和类型卡片布局未命中。显式合并 extCls 与已有 class，保留 name、requiredMark、rules、插槽和其他属性。
6. 兼容侧栏及 ES 侧栏头部按 V2 恢复 52px 高，左右留白 20px。Grok 原有内容留白和动作区 88px 按钮、8px 间距继续由自身样式控制。

## 实际对照结果

本批视口为 1728×873，同一标签页逐次切换两版；侧栏仅打开初始新增表单，没有执行提交、连通性测试或已有资源编辑。

- 归档策略：宽度均为 676px。V3 提交/取消由 56×32px、12px 字号、无间距，恢复为 V2 的 64×32px、14px、间距 10px。表单项起点分别为 y=80/152/224，按钮 y=328，V2 对应 y≈328.3；此前 V3 按钮 y=364。主要尺寸和位置通过本批对照。
- 归档仓库：集群行恢复横向布局及 32px 高，类型卡片行恢复 108px 高，动作按钮 64×32px/10px 间距。V3 按钮 y=746，V2 y≈750.8，仍有约 5px 的累计高度差，主要发生在说明/输入区，未声明整页像素完全一致。
- 归档回溯：保留 18px 上边距，不套用策略页面的 8px。V3 按钮 y=502，V2 y≈503.6；按钮尺寸和间距一致，剩余约 2px 累计差异未清零。
- Grok：640px 侧栏、560px 内容宽度、52px 头部，提交/取消继续为 88×32px、间距 8px；公共修复没有覆盖其专属动作布局。
- ES 集群：实际打开 640px 侧栏，进入视口后确认头部 52px、提交/取消 64×32px、间距 10px。没有测试连通性、提交或全部存储分支；不能据此标记全业务通过。

## 回归步骤与结果

1. 同一视口打开 V2/V3 归档策略新增，比较三个表单项和动作区，确认按钮不贴边、文字不是 12px、表单下方不多出默认 24px 间距。
2. 仓库新增重点检查 ES 集群横向行、类型卡片、500px 输入区与动作区；回溯新增检查五个字段之间的 18px 上边距。
3. Grok 检查 88px 动作按钮与 8px 间距，不能被归档的 64px/10px 规则覆盖。
4. ES 打开后检查实际进入视口，不能将停在屏幕外的隐藏 Drawer 几何误计为验收通过。
5. 扩展表单项适配回归：`ext-cls` 和已有 class 必须合并；字段名、必填、rules 对象及默认插槽保持原值。合成测试位于 `tests/management-overlays-native.test.mjs`，不使用真实业务数据。

定向执行两个管理测试文件，8/8 通过；全量 435 项中 429 通过、6 项已有失败，与上一批失败范围一致，涉及迁移工具入口缺失及源码基准漂移。生产构建、AI 索引检查和 diff 空白检查通过。构建产物及运行日志仅位于仓库外临时目录。构建仍存在既有大 chunk 警告，不影响本批构建成功结论。

本批未重新执行严格类型检查及 APM/Trace 构建；没有新增状态或服务协议。其余独立侧栏、编辑回填、错误提示、多分支内容及窄屏滚动仍需后续逐项验收，不能以共享样式生效替代完整验收。
