## 检索域本批改动

新增 `packages/web-v3/src/app/state/domains/retrieve-store.ts`，使用原生 `defineStore`、独立状态工厂、派生值和具名 action；`application-runtime.ts` 的 retrieve 域改为连接该原生 store，不再实例化通用转换器中的 retrieve 状态。

保留源码中的完整行为：

- 索引 ID 字符串化、权限权重排序、父子节点标识、删除 parent_node、索引简称截断、树和扁平列表。
- 查询前清空列表、loading 可选设置和 finally 恢复、失败向调用方传播，以及 `[原响应, 处理后列表]` 返回协议。
- 场景加载使用 action 所属的明确 Pinia 实例读取业务 ID；不依赖异步执行时的全局 activePinia。失败回填空列表、派生转换及 finally 恢复均保留。
- 字段配置合并的默认值、fixedFilterAddition 保留规则、空 addition 不覆盖旧配置、运行态清理时不重置 shell 就绪标志，均按原方法保留。
- 缓存时间、版本、趋势、总数和首屏就绪状态保留独立具名写入。

迁移 37 个业务文件中的 89 处检索域调用，随后补迁移导出日志和旧结果页中的 3 处 mapState 回调读取。调用由命名空间字符串转为 `useRetrieveStore()` 的属性/action；主应用、场景、收藏、字段、趋势及 Monitor 初始化均涉及。初始 37 文件清单保存在证据目录的 `retrieve-callers.json`，不将调用数当成功能覆盖率。

仍有过渡边界：`retrieve.js` 保留旧协议声明供现有运行时解析；兼容视图直接指向原生 `$state`，不复制状态。根 action 仍通过旧命名空间协议访问它。只有根状态和其消费者迁完后，才能一起删除旧声明及转换器。不能将本批解释为所有 Pinia 工作完成。

## 聚类确认交互与细颗粒度主题

规则模式切换改为原生 TDesign Popconfirm，保留 V2 的“请求切换—确认前回滚—确认后应用”流程和配置清空提示，不提前修改规则。模板解绑等其他确认入口尚未全部替换。

本批真实交互发现并修复两类问题：

1. 单选 change 设置弹层可见后，同一 click 的 TDesign 触发回调又请求关闭。现在区分触发来源，忽略同次 trigger-element-click 的关闭请求；取消、确认和外部关闭仍正常处理。
2. 取消前视觉样式回到模板，但原生 input 的 checked 曾出现两项同时为 true。回滚后重建单选输入，保证 DOM、可见样式和业务模式一致，并能取消后再次打开确认。

样式按 V2 实测处理，局部约束，不更改全站控件：

- 去掉 TDesign 单选组合额外的 24px 项间距、标签默认 margin，并保留原来的 16px 组合间隔；组合总宽度 112px。
- 确认层宽 288px，去掉多余图标和双重内边距，恢复“确认切换在左、取消在右”、小号按钮和提示字号。
- 避免全局主题的 `row-reverse` 和按钮 padding 覆盖本模块。最终 V3 弹层实测 288×124；V2 截图高度约 128，仍有少量纵向差异，不宣称像素完全一致。

## 对上一批表格差异判断的修正

上一批将 1280 小视口、收藏栏展开时 Pattern 过窄列为待核对差异。本批对照同业务、同窗口的真实 V2/V3，两个版本各列实际宽度均为：125、91、96、108、200、200、200px，Pattern 的声明同为 min-width 350px、实际 width 108px。V2 源码也保留同样的表格布局规则。

因此此场景属于两版共同表现，不再作为“迁移丢失”的已确认缺陷，不在迁移中单独增加列宽规则。历史报告保留，本记录补充纠正。其他视口、拖动、分组、时间对比下的列宽与滚动仍待覆盖；整个表格未验收通过。
