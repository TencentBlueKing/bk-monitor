# 实施记录 07：采集标签过滤样式与外部关闭

日期：2026-11-12。依据 V2 采集列表与实际 `retrieve-v2/search-result-panel/log-clustering/components/finger-tools/cluster-filter.tsx`、同目录 SCSS、bk-magic-vue Select 搜索及扩展区源码/CSS，修复 V3 对应共享 ClusterFilter。没有改业务资源。

## 1. 根因

调用方 `features/collection/current/components/list-main/table-list/table-list-v2.tsx` 使用 `ClusterFilter` 展示标签筛选。V3 已改原生 TDesign Popup，但只传入 visible，缺少 onVisibleChange，因此 Popup 检测到外部点击后，关闭提议没有回写到 isShowSelectOption，菜单保持打开。搜索框、按钮及触发器继续使用默认 TDesign 尺寸；TPopup 的 class 未落在实际触发 DOM 上，原 `.cluster-select-filter .filter-box` 样式也没有命中，导致触发点高度、漏斗颜色及弹出位置偏差。

## 2. 修复

修改文件均相对 `packages/web-v3/src/`：

- `features/retrieval/workbench/search-result-panel/log-clustering/components/finger-tools/cluster-filter.tsx`：接收 Popup 的关闭事件；只有当前已打开且收到 false 时执行原 `toggleSelect(false)`。搜索框或弹层内焦点触发的 true 不重复重置选择草稿，已关闭的重复通知不再调用 toggle。
- 仍由调用方原 `handleToggleTagSelect` 按已应用 filterValue.tags 恢复 tagSelect。关闭清空 keyword，不提交筛选；确定继续由原 submit 事件执行原 tags 条件和 reloadList。取消继续调用原 cancelFilter。没有改变全部/单项选择的互斥逻辑、服务请求或权限。
- 给实际触发 div 独立类 `cluster-select-filter-trigger`，恢复 12px 字号、16px 行高及原漏斗状态色；不依赖 Popup 转发 class。
- 同目录 `cluster-filter.scss`：200px 最小宽度、1px 边框、2px 圆角；搜索区域为搜索图标+底边框，恢复“输入关键字搜索”及原 placeholder 色，去掉 V2 不存在的额外 clear 按钮；列表上下 6px、左右 16px，32px 选项行，文字 12px/18px、复选文字间隔 6px；底部 1px 分隔线、12px/16px 内边距，按钮 64×26px，间距 8px。Popup 与触发点距离 4px，窗口边界保留 4px，避免贴住右侧边缘。

后续修改 Popup/Select/Checkbox/主题时，按此顺序重复：

1. 完整刷新采集列表，打开标签过滤；比较默认、输入搜索、选中、按钮 hover 及窗口右边缘的实际挂载 DOM 和 computedStyle。

5. 在 `packages/web-v3` 运行 `node --test tests/collection-tag-filter-native.test.mjs`；共享组件修改继续回归全量测试及主应用/APM/Trace 构建。保留长列表滚动、其他语言及其他模块调用方待验证项。
