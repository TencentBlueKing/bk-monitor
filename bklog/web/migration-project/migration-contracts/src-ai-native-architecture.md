# Vue3 主目录架构决策

日期：2026-10-28。依据：TAPD 139460519、全量组件迁移实施计划、full-business 验证记录、当前 src-native 的 1315 个文件。用户认可当前目测效果；不等价于所有业务分支已经验收。

## 事实与问题

src-native 是当前运行依据，包含 Vue3 升级后的完整业务以及必要兼容层。原 src 是早期简化原型，不能作为业务基线。业务入口分散于 views/retrieve、retrieve-v2、retrieve-v3、manage、manage-v2；名称不能代表运行时 Vue 版本。全局 store、缓存、hooks 与业务组件存在真实交叉引用，直接搬目录或同时重写状态会扩大回归面。

## 决策与边界

本次按责任拆分文件归属，并根据实际引用重写模块路径；不改变 API、路由、权限、字段及组件契约。保留版本条件分支，通过 classic/workbench/workspace 和 classic/current 标识实现代际，不误称为 Vue2/Vue3。

- app：启动、根视图、路由、全局状态与初始化。main.js 只装配启动入口。
- features：检索、采集、清洗、归档、提取、集群、仪表盘、授权、分享等业务域；对应服务及专用组件归入同一域。检索的共享内核显式保留。
- platform：请求协议、持久化、语言、监控和 Vue/控件兼容。兼容债务集中呈现，不声称已经清零。
- shared：无明确单域归属的 UI、hooks、工具、指令、样式、图像及静态资源。跨域共享 hooks 暂不拆业务行为，其依赖进入图谱供后续治理。

不强行引入新的全局状态框架，不为 AI 新增后端协议。保留 @blueking/date-picker。TDesign 及剩余兼容控件的事件/样式次序保持。源文件映射、一对一完整性、静态依赖图、现存跨层依赖是本次可核验的交付；业务逻辑深度重构按模块契约另行推进。

## AI Native 协议

建立 ai-native 目录，保存模块描述、源码来源映射、静态依赖、任务及失败记忆格式。context 命令按模块或变更文件生成有数量上限的上下文；impact 命令反向遍历引用并给出受影响模块、路由与建议测试。check 门禁防止丢文件、遗留 src-native 运行引用、源快照漂移及无记录的依赖变化。图谱记录静态可解析引用，动态计算路径必须保留并单独人工验证，不伪造完整动态调用图。

模块描述与图谱由真实文件产生，不让描述替代源码。新增能力必须明确契约、测试、验证证据；BLOCKED/NEEDS_REVIEW 不自动提升为 ACCEPTED。复用 migration-project 既有台账及验证资产，不再建设另一套代理平台。

## 实施与准入

1. 原 src 归档并记录 SHA256，保留 src-native 对照；确定路径映射与引用关系。
2. 按上述责任域生成目标文件，保留业务逻辑，重写静态引用、样式及资源路径、worker 和 glob；不使用指向 src-native 的别名或软链接。
3. 默认开发/构建切至新 src；基线命令单独保留。迁移现有 65 项契约测试，使其实际加载新 src。
4. 执行完整性门禁、契约测试、生产构建，以及真实浏览器检索和管理入口只读对照；失败先定位根因。
5. 记录结果和剩余兼容/类型债务。保留原全量验收状态，不把目录架构迁移当成全业务验收或 V2 退役。

回滚：停止新开发进程，使用 dev:baseline 运行 src-native；原型归档仅用于追溯，不作为业务回滚版本。
