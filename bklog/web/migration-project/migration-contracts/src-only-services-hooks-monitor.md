# Vue3 单源码目录、类型化服务、Hooks 与 Monitor 交付契约

## 目标

最终仅以 `packages/web-v3/src` 为应用源码入口，融合并移除 `src-native`。迁移过程中保持 V2 的后端协议、业务分支、交互和已验证的 Vue3 页面；严格类型检查必须通过，不能通过缩小检查范围或忽略诊断验收。

## 架构落点

- `platform/services/runtime/service-client.ts`：端点定义、类型化模块工厂和延迟传输注入。认证、空间头、取消、缓存、错误及 Blob 协议继续归 HTTP 层负责。
- `platform/services/index.ts`：唯一的 `ServicesInstance` 和 `useServices()`。调用形式为 `ServicesInstance.retrieve.getLogTableHead(options, config)`；模块与操作名来自实际端点定义。不存在的操作必须报类型错误。
- `features/*/services/*.ts`：各业务模块拥有自己的端点与 DTO；平台服务文件只处理空间、用户、配置等平台能力。
- `app/bootstrap`：组装端点和客户端，先完成服务安装再启动应用。Store 和平台传输不得在模块初始化阶段反向读取尚未初始化的全局客户端。
- `shared/composables`：跨业务的组合能力。业务专用 Hooks 保留在所属 feature。Mixin 的隐式字段、事件、watch 和清理动作需要逐项变成显式参数、状态和返回值。
- `app/entries`：日志应用、APM、Trace 的独立入口；三者共享业务源码，独立选择构建分支、初始化和输出形态。

## 分批执行与验证

1. **服务收敛**：端点定义转 TS，替换静态、条件和配置选择的旧 `http.request(path, ...)` 调用。缓存及诊断所需的端点身份使用操作的只读 `id`，不能恢复通用字符串分发入口。同步导出的真实 URL 保留在 Blob 下载边界。
2. **JS 收敛**：按服务定义、应用启动/路由、Store、HTTP、共享工具/指令、兼容适配的依赖顺序转 TS。逐批同步 import、测试和 AI 索引；生成的第三方静态产物与应用源码分开管理，不用 `any` 或忽略注释掩盖迁移诊断。
3. **Mixin 收敛**：先迁移文档导航、侧栏未保存校验，再处理空间选择、拖拽、采集列表、存储表单和日志展开。兼容宿主的全局 Mixin 也需改为明确的组件适配安装，不将业务 Mixin 改名后继续合并。
4. **Monitor**：沿 `monitor-apm-retrieve`、`monitor-trace-retrieve` 及监控侧实际消费点核对导出、初始化顺序、Vue 宿主、Store、i18n、样式、Worker、资源公共路径和条件分支。先构建到隔离产物目录，通过宿主验证后更新交付产物；不调用自动升级/发布版本脚本。
5. **单目录退役**：校验功能与构建后归档 `src-native` 的源码、哈希及基线契约。将依赖旧路径的验证改为读取可追溯的冻结契约，清理旧入口、配置和脚本，最终删除旧源码目录。

## 验收门槛

- 根 `bklog/web` 默认 Dev 启动 `web-v3`；V2 仅保留显式对照命令。
- 业务调用不再使用任意服务路径字符串；统一服务工厂、模块名和操作可进行 TS 检查及 AI 影响分析。
- 应用源码中的独立 JS 文件和业务 Mixin 清零，现有业务功能与原有接口序列保持一致。
- APM/Trace 独立构建与实际宿主运行通过，保留已公布的兼容协议并明确 Vue3 入口。
- 严格类型检查、自动测试、生产构建、关键浏览器场景通过；仅剩 `src` 作为应用源码，不再依赖 `src-native`。

## 本批已落地

根 Dev 已改为 Vue3，原命令保留为 `dev:v2`。36 个服务定义模块中的 427 个端点已接入 TS 定义工厂；统一客户端、延迟注入、同一全局实例及按模块访问已经建立。业务调用正在逐项替换。端点语义、请求参数以及取消配置的测试已增加；AI 影响分析已开始识别具名服务调用。以上仅为本批进展，不代表全部验收完成。
