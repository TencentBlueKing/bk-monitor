## 修复及源码依据

- 管理入口显示 `[object Promise]`：`router/manage.js` 中版本包装器沿用 Vue2 的异步工厂渲染。使用 `defineAsyncComponent` 包装被嵌套渲染的 loader，保留原特性开关、懒加载和 `showSubNav` 分支。新增 `router/async-view.js`，测试分别验证两个版本分支及布局参数。
- JSX 协议：按 AST 升级事件属性、`scopedSlots`、直接命名子插槽、监听器对象和 props/attrs/domProps 包装层。保留回调表达式、参数、对象展开次序及默认子节点；未据此重写业务逻辑。新增变换覆盖、幂等性测试，并保留每批变换文件清单。
- Vue2.7 控件的槽位回退函数：Vue3兼容层按旧数组协议处理，产生异常 Fragment。`adapters/tdesign/legacy-slot.js` 使用原生 `renderSlot` 兼容数组/函数回退，保留已有槽位的惰性语义和绑定参数。诊断发现 `_t` 在实例上下文中是 getter，普通赋值不生效；最终通过应用 mixin 和可配置属性替换生效。
- 旧表格：`refInFor` 元数据没有转换到 Vue3 的 `ref_for`，导致单行引用不是数组。迁移配置只对剩余 `bk-magic-vue` 的构建输入转换此元数据，不修改安装包或压缩产物。列组件在 `created` 中改写实例 render，还需在挂载前同步；区分单元格作用域插槽与普通分组子节点，避免在隐藏列注册树中执行需要 `row` 的插槽。源码增加显式单元格插槽标记，保留真实单元格渲染。早期无区分同步产生 `row undefined` 的尝试已撤回并保留原因记录。
- 控件导入：V2 的 Babel 插件会把 `Button`、`InfoBox` 等名称转换为旧库真实导出。目标缺失此步骤，导致控件 undefined、确认函数不可调用；已按真实导出修正引用。该兼容修复不计为全部基础控件已升级到TDesign。
- 采集及模板公共表格仍导入 Vue2 `tdesign-vue`：切换到 `tdesign-vue-next` 与对应样式，保留专用列、槽位、分页、筛选、排序、列宽和请求处理函数。真实采集列表恢复127条总数、当前页10条，12个业务表头与V2对照一致。
- 公共 LogButton 的 `type: Object | String` 实际为位运算数字，触发 Vue3 属性校验异常，导致有总数但无数据行；修正为构造器数组 `[Object, String]`。
- 字段树预编译函数式组件缺少 Vue2 模板上下文辅助器：仅对 `bkBigTree` 的局部组件树补齐上下文，保留节点属性、事件和槽位。38131真实非空日志及趋势恢复，KV/JSON展开、收起、原始模式切换通过。
- `use-router` 的 V2 调用契约为 `currentRoute.query`，Vue Router 4 实际返回 Ref。通过 hook 边界的响应式 facade 保留旧业务读取协议，并修复监控初始化读取；测试验证查询、未知参数、动态参数和导航。
- 静态资源：归档仓库、图表和行操作图片改为ES导入；采集类型卡片的 `require.context` 改为同范围、非递归PNG的 `import.meta.glob`。IP选择器改用安装包提供的官方 `dist/vue3.x` 桥接入口，保留原服务、面板、值和事件配置；官方桥接内部仍包含独立Vue2，未声称该依赖已纯原生化。
