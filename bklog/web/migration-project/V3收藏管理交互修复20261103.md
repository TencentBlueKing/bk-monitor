# V3 收藏管理交互修复（2026-11-03）

本批状态：实施中，业务和视觉均未整体验收。依据 V2 retrieve-v2/collect 下三个原组件，恢复现有收藏管理，不增加后端协议。

## 源码与原因

- V3 `features/retrieval/workbench/collect/favorite-manage-dialog.vue` 仍使用旧 Dialog/Table/Form/Popover，点击入口无法显示有效管理界面。
- Vue2 兼容模式会将 modelValue 改写为 value，而当前父组件传入 Vue3 modelValue；组件明确关闭 COMPONENT_V_MODEL 兼容，保持父组件原 close 事件。
- 原先的旧表单 validate 在校验失败时 reject；TDesign 返回错误对象。仅等待 Promise 会造成无效表单继续写入，已增加结果必须为 true 的准入判断。
- 旧 Table 的隐式列、复选、筛选、排序和编辑事件均需显式映射，不能仅替换标签名。

## 实现范围

- 收藏管理使用原生 TDesign Dialog、Table、Form、Input、Select、Option、Popup；顶部 50px 保留导航，管理头部 48px，与 V2 布局对照修正。
- 六列表格完整保留：多选、名称、所属组、变更人、变更时间、操作。保留分组筛选、收藏搜索、列多选筛选的确定/重置、时间排序、详情和行编辑入口。
- 原生表格中默认新增的筛选汇总行予以关闭；窄表格单元格、标题继续按 V2 截断，不允许时间字符串撑大行高。
- 新建分组保留原格式、重名、必填、30 字限制；普通/场景 source_type、空间及 APM scope 沿原组件协议传递。
- 批量菜单使用两层受控 Popup，保留悬停移动分组、新建分组、批量删除。body 托管的二级菜单点击属于父菜单内部；打开删除确认时清理两个菜单层。
- 详情组件使用原生 Select，统一字符串选项比较，保留 null 分组请求表达。新增 favorite.types.ts 描述已有字段，查询条件、IP 选择及显示字段均完整透传。
- 单项删除使用原生 DialogPlugin，成功后才更新本地列表并关闭确认。
