# V3 迁移进度分析与后续完善计划

日期：2026-10-28  
需求：[【日志前端】AI Native Web开发探索（AI Migration Engine）](https://tapd.woa.com/tapd_fe/10158081/story/detail/1010158081139460519)  
分支：`feat/ai-migration-engine/#139460519`  
性质：分析与评审建议，待用户决定实施；本次不修改业务实现、不调整既有阶段状态、不提交或回填 TAPD。

## 1. 分析结论

**当前 V3 属于“工程底座 + 局部检索能力 + 多路由列表原型”，尚未形成通过验收的完整迁移模块。用户手动测试反馈的功能与 UI 交互还原度低，与当前源码和验收证据相符。**

主要问题不是最后一轮样式精修不足，而是迁移方法没有落实 TAPD 的“旧版行为基线 → 组件契约 → 完整试点 → E2E 与视觉回归 → 批量推广”闭环。大量旧版页面被统一列表替代，复杂交互没有迁移；缺少运行态基线，又使视觉差异无法被持续发现和阻断。

建议保留已验证的工程隔离、请求参数、状态逻辑和工具雏形，暂停继续扩大页面壳覆盖。先补 P1/P2/P3 的必要证据和门禁，再完成 P4。检索页作为首个用户可见的完整恢复试点，采集向导作为验证复杂表单与写入流程的第二试点；二者通过后，才恢复 P5 批量迁移。

### 1.1 进度不能用路由数量替代

- 已提取 87 条具名路由，是路由映射资产，不是 87 个页面完成迁移。
- 非检索路由多数复用 `ResourcePage.vue`，展示接口返回的通用表格。新建、编辑、详情、操作流程并未因此实现。
- 当前没有证据可将任何完整业务模块认定为 TAPD 定义的 `ACCEPTED`。这表示“完整模块验收尚未建立”，不表示已有代码没有价值。
- 缺少完整场景分母、执行结果和稳定截图，不能负责任地给出全项目功能或 UI 完成百分比。
- 推荐项目状态描述：**P0/P1 有基础资产，P2/P3 不完整，P4 未通过，P5 有提前探索成果，P6/P7 未具备完整验收证据。**

### 1.2 证据边界

本次读取了 TAPD 需求正文、当前迁移说明、阶段材料、任务 JSON、V3 路由/页面/API/适配器/测试和部分 Vue2 路由源码，并复跑 V3 现有测试。用户本轮手动测试反馈作为定性运行证据。

本次没有重新开展双端浏览器全量走查，没有采集新截图，没有执行真实新增、编辑、删除等写入操作，没有重新验证生产构建、部署和回滚。迁移说明中 2026-10-27 的检索结果和采集列表行数属于历史记录，不写成本次复测结果。具体视觉尺寸、像素差异和全量权限行为仍待实测。

## 2. 按 TAPD 原始阶段重新评估

`迁移说明.md` 中的“P1 workspace 隔离”与 TAPD 的 P1 定义不一致。TAPD 将环境初始化归 P0，将旧项目自动化分析归 P1。后续应统一口径，避免阶段编号造成完成度误判。

### P0：工程初始化与基线冻结——有基础，需补可复现证据

已具备源/目标目录、分支、包管理器隔离、启动配置及历史可访问记录。Vue2 保留 npm，Vue3 在独立包中使用 pnpm。

仍需将源码版本、当前未提交差异、依赖锁文件、环境、账号角色与数据前置条件绑定到一次基线记录。当前工作区已有多项未提交修改，后续不能只用 Git HEAD 标识待验收的实际代码。

### P1：旧项目自动化分析——部分完成

`migration-plan/02-legacy-analysis.md` 与 `artifacts/analysis/` 已形成静态清单：历史扫描记录 88 个带 path 对象、468 个组件/页面文件、29 个 store 文件、46 类 bk-* 标签。以上是文本扫描口径，不是本次重新统计的准确业务分母。

`analyze-legacy.mjs` 主要使用正则和目录扫描；TAPD 要求的 AST/模板分析、状态与事件依赖、动态分支及影响分析尚不能认为完整。应先对首个试点补准确依赖链，不必立即构建全仓复杂分析平台。

88 个带 path 对象与 87 条具名路由统计对象不同，应建立逐项对账；不能直接把差值算成漏迁一页，也不能直接视为全量覆盖。

### P2：业务行为与 UI 基线——明显不足，是首要短板

`03-business-behavior-matrix.md` 仅有采集标签和应用类型的 9 个源码场景，并明确没有运行时确认。检索已有历史人工核对，但尚未形成完整、可执行的统一场景矩阵。

`05-ui-baseline.md` 明确：打开过检索页，采集向导基线未采集；纯色图和 `.ai-native/` 图片不作为 UI 基线。尚不能据此完成默认、交互、异常及弹层状态的视觉回归。

### P3：迁移引擎与组件适配层——工具雏形可复用，不能视为整体完成

已有兼容规则 JSON、契约提取器、Button/Input/Select 等映射、两个局部适配组件、状态函数及 PNG 比较器。

但 `p3.json` 仍列出 right-icon、select toggle context、dialog、tree、checkbox 等缺口；`run-p3.mjs` 用 2×2 纯色图验证比较器。它没有证明真实业务组件的跨库交互与视觉保真。

`main.ts` 引入 TDesign 部分样式，实际检索页大量使用原生按钮/输入/选择控件；当前路由页面没有引用两个试点适配组件。适配器测试通过与业务页面采用适配层之间存在断点。不能将“依赖已安装”视为组件库迁移完成。

### P4：典型业务模块试点——未达到通过条件

`artifacts/tasks/p4.json` 为 `NEEDS_REVIEW`。主要成果是标签选择、应用类型状态与局部渲染验证，没有整页采集向导、E2E 和视觉闭环。

其中 `pageCheck.reachedRetrieve` 是检索页访问证据，不能验收采集模块。`run-p4.mjs` 仍可能写回早期登录阻塞和缺少 E2E 的字段，与已人工更新记录存在口径差异。后续应让验收由实际产物生成，避免脚本重跑覆盖事实。

### P5：按依赖批量迁移——已有原型，未满足准入

TAPD 明确要求 P4 通过后才正式开始 P5。当前配置 phase=P5、任务状态 `NEEDS_REVIEW`，并不代表 P0～P4 已全部通过。

可以保留路由和列表请求探索结果供后续使用，但不能沿用“逐个路由接列表接口”的方式宣布页面迁移。每个业务模块必须独立恢复并验收。

### P6/P7：回归发布与 AI Native 固化——未证明完成

未发现覆盖本次迁移的完整全量回归/上线报告，`08-acceptance-report.md` 尚不存在。规则、契约、任务记录已是 P7 的种子资产，但缺少可靠的场景关联、失败记忆和强制准入机制，不能视为可持续迁移引擎已交付。

## 3. 功能与交互差距

### 3.1 检索：局部可用，离完整替代仍有明显距离

可复用：真实索引集/字段/检索/趋势请求，查询体构建、字段分组、排序、条件追加、原始/表格切换、部分行展开、聚类开关状态判断。历史说明记录了索引集 38131 的局部人工验证。

已知未恢复：收藏、场景化检索、历史查询、完整 UI/SQL/AI 输入模式、JSON 格式化、划词高亮、级别色条、展开侧栏、字段拖拽与设置、下载、实时日志、趋势图完整操作、分享/配置/用户入口、聚类接入向导和完整 Pattern 操作。

当前源码可确认“场景化检索”按钮没有点击逻辑。这属于功能缺失，不能用按钮外观相似视为已还原。

请求可靠性还需专项验证：

- `RetrievePage.vue` 的检索与趋势使用 `Promise.all`，趋势失败会进入同一 catch 并清空检索结果。应先对照旧版期望，再决定失败隔离方式。
- 索引切换时字段加载与查询并行，字段加载错误被吞掉；快速切换后的排序、字段和结果一致性缺少验收证据。
- 未看到检索请求使用取消或响应版本校验，慢旧请求可能覆盖新请求是静态风险，尚未通过浏览器复现，不能写成已确认线上缺陷。
- 现有查询测试断言了固定输入输出，没有覆盖真实输入控件、路由切换、网络失败、分页/加载更多和多请求时序。

### 3.2 管理页：通用列表是主要替代，不是业务迁移

`ResourcePage.vue` 从返回首行猜测最多六列，直接显示字段 key 和字符串值，仅提供加载及错误信息，没有对应业务的筛选、分页控制、表单、校验、操作列和提交流程。

`resolveFeature` 按路由名归类，例如 `collectAdd`、`collectEdit` 仍归采集列表接口；仪表盘创建/导入路由归目录树接口。它证明入口被归类，不能证明新建或编辑行为存在。

采集、索引集、清洗、脱敏、提取、归档、订阅、集群管理等应分别建立“列表 → 操作入口 → 表单/详情 → 提交 → 结果回显”的流程契约，不能只补表格文案。

### 3.3 全局导航与平台行为：需要单独恢复

当前壳只包含简化品牌、空间展示和四个导航。迁移说明已记录“监控策略/仪表盘”从旧版外部打开改成 V3 站内页，这属于业务导航变化，应默认恢复旧行为；若希望改产品行为，另行评审，不能混入等价迁移。

Vue2 `src/router/index.js` 中存在路由切换取消请求、父窗口通信、外部版路由限制与路由上报；当前 V3 路由只还原基础 name/path/title 和重定向，没有对应守卫/钩子。应逐项核对是否适用于目标部署并迁移，不能只复制具名路由。

当前 API 客户端只做基础 fetch、空间头和响应解析。认证过期、无权限、CSRF、取消、错误分流等须对照 Vue2 公共请求链确认。本次未作完整权限审计，不将这些待核对项一概认定为已复现缺陷。

### 3.4 UI：结构、状态和组件行为要一起恢复

当前视觉差距有结构性原因：收藏区/操作区缺失、复杂输入框被简化、业务弹层未实现、通用表格替代专用页面、适配组件未接入。单纯调整间距和颜色无法解决。

后续按“页面区域与信息层级 → 交互状态与弹层 → 控件契约 → 字体/尺寸/颜色/图标细节”修复。TDesign 可以作为基础组件实现，但页面组合和状态反馈应以旧版为准，不能照搬其默认示例重新设计页面。

## 4. 根因与改进方向

1. **完成口径失真。** 路由映射、API 返回、局部测试被当成业务进展。改为场景级验收，路由覆盖单独统计。
2. **基线不足便开始扩面。** 源码扫描不能替代真实交互。先补旧版试点场景与截图，未知行为留待核实。
3. **状态逻辑、适配组件与真实页面脱节。** 后续必须验证页面实际使用了哪份契约和组件，禁止只测试旁路示例。
4. **试点没有形成端到端闭环。** P4 未过就扩展 P5，将简化实现扩散到多个入口。通过真实试点验证方法后再推广。
5. **门禁偏向能跑而非保真。** 当前测试不覆盖用户主要操作与 UI 状态。让任务状态依赖构建、场景、E2E 和视觉产物，缺任一必要产物不得接受。
6. **历史记录缺少一致性约束。** 阶段编号、路由口径、脚本和人工记录有偏差。绑定代码版本、场景 ID、环境、执行时间和报告路径，禁止用旧报告验收新代码。

这些是依据现有实现与资产作出的工程判断；本次不归因于某个模型能力，也不建议先投入大型多 Agent 平台。

## 5. 后续实施计划（待决定后执行）

### R0：纠正范围、台账与验收口径

目标：先能准确回答“哪些功能没有迁移，哪些只是没验证”。

- 对账 Vue2 路由、嵌套路由、布局容器、重定向、外链与动态入口；标出对应 V3 实现、真实功能、接口与权限依赖。
- 状态分为：未实现、原型/占位、部分实现、待验证、验收通过、阻塞。不可把存在页面统一标为完成。
- 为每个范围内的旧行为记录：保留、等价替代、经批准移除或待确认；默认保留，不由 Agent 自行删减。
- 对用户本轮手测问题建立可复现差异项；缺少细节时可从旧版与 V3 对照补充，不依赖用户重新整理全部问题。
- 记录源码快照和未提交差异，统一阶段编号及历史报告适用范围。

建议产物：`migration-plan/09-route-and-feature-ledger.md`、`10-gap-backlog.md`；更新范围、风险与验收报告。每条差异绑定旧版证据、V3 位置、优先级、场景 ID 和验收方式。

通过条件：首个试点无未登记入口/关键行为，所有占位页明确标识，阶段状态与证据一致。

### R1：补齐试点的旧版业务与视觉基线

首选检索页，沿用 38131 和同一空间作为已有证据入口，但需要补多数据形态及权限角色，不能只验一个索引集。

- 按实际源码与运行行为建立检索场景：索引切换、时间范围、输入模式、条件操作、排序、结果加载、字段设置、详情、收藏/历史、聚类与分享等。
- 分离“必须通过的关键场景”与其他范围内场景；两者都应进入台账，不能把难项从分母中移除。
- 固定窗口尺寸、缩放、字体、语言、时区、角色、数据和绝对时间范围；采集默认、展开、选择、弹层、加载、空、失败和无权限状态。
- 数据与视觉基线可用脱敏固定响应保证稳定，另用同环境真实接口验数据契约；相对时间窗口行数不作为等价判据。

建议产物：扩充 `03-business-behavior-matrix.md`、`05-ui-baseline.md`；按场景保存基线与数据说明，后续补 `migration-contracts/pages/retrieve.*`。

通过条件：关键路径有实际旧版证据、可执行步骤和明确预期；截图能重复采集；不明行为登记阻塞，不由 Agent 猜测。

### R2：补最小公共能力，并接入真实页面

范围以试点需要为限，按依赖准备：

1. 全局导航、空间切换、路由/外部部署语义、公共请求与错误/权限反馈。
2. Button/Input/Select、弹层、表格、树、时间选择等实际需要的组件契约，明确 props、事件、插槽、v-model、禁用/加载、焦点、关闭与销毁行为。
3. 页面布局、字体、控件尺寸、颜色、层级和弹层挂载等样式约束。
4. 可重复截图采集、区域差异图、差异报告与页面 E2E 最小流程。

建议优先复用项目已有测试能力，必要时引入浏览器测试；不为满足目录模板复制一套工具。纯 PNG 精确比较保留为底层工具，但需要稳定化、局部差异定位和人工复核规则，不能要求新旧不同组件库所有像素完全相同。

通过条件：上述能力在真实检索页面运行，测试从页面操作出发，截图比较能发现已知差异；旁路演示与纯函数通过不能单独验收。

### R3：检索页完整试点，逐块恢复并验收

建议顺序：

1. 全局壳/导航 → 空间与索引状态 → 时间与完整查询输入 → 检索/趋势与请求时序。
2. 结果加载、排序、原始/表格、详情、字段选择/设置/拖拽、高亮与格式化。
3. 收藏、历史、场景化检索、下载/实时日志、分享/配置及聚类分支。

每块以旧版契约限定范围，完成“实现 → 契约/组件验证 → 浏览器交互 → 视觉差异修复 → 记录”后再进入下一块。UI/SQL/AI、聚类等若受后端开关或数据限制，应单列阻塞与补测条件，不能因此宣布整页通过。

通过条件：约定范围内的检索行为都有去向，关键场景全部通过，无未批准的功能遗漏/高影响 UI 差异；构建、真实链路、E2E 和视觉报告绑定同一代码快照。若仅交付部分范围，应标为局部验收，不冒充完整检索替代。

### R4：采集向导第二试点，验证复杂写入流程

复用已有标签与应用类型状态资产，但必须连入完整页面。

- 覆盖采集列表进入新增/编辑、环境/目标选择、字段联动、标签树、应用类型、步骤前进/返回、校验、提交、结果回显与再次编辑。
- 覆盖取消、重复提交、接口失败、过期响应、无权限及不同采集场景。
- 写入测试使用隔离测试业务/资源，记录清理方式。页面要以旧版真实分支确定步骤，不能预设所有场景同一表单。

通过条件：至少一条完整采集新增及编辑流程通过端到端验证，关键业务分支有对应测试/证据；复杂弹层、联动及异常 UI 通过复核。通过后方可认可现有 P4 的完整试点目标。

### R5：按业务模块恢复批量迁移

建议依赖顺序：已验证公共能力 → 采集/索引集管理 → 清洗与模板/Grok/脱敏 → 提取与链路 → 归档/恢复 → 集群/订阅/设置等。实际次序由路由台账与组件/接口依赖复核后确定。

## 6. 建议验收机制与进度指标

### 6.1 四条验收线分别记录

- 工程：依赖隔离、静态检查、构建和部署是否通过。
- 业务：事件、状态、请求、校验、权限、异常恢复与旧版是否等价。
- UI/交互：区域、控件、弹层、关键状态与操作反馈是否还原。
- 工作流：任务输入、源码快照、基线、执行记录与失败处理是否可复现。

工程测试通过不能抵扣业务与视觉失败。阶段准入要检查上一阶段的必要证据，任务到 `VERIFYING` 后，只有门禁满足才可 `ACCEPTED`；未知或缺环境则阻塞相关场景，不能计入通过。

### 6.2 进度按固定分母统计

- 业务验收覆盖率 = 已通过场景数 / 范围内全部场景数；关键场景另列通过/总数。
- UI 状态验收覆盖率 = 已通过状态数 / 范围内必测 UI 状态数。
- 模块完成度 = 完整验收模块数 / 范围内业务模块数；部分实现单列。
- 差异负债 = 未解决功能遗漏、高影响视觉差异、阻塞项的数量与分布。
- 路由访问覆盖率单独呈现，仅用于入口检查。

当前尚未建立分母，不输出推测百分比。也不建议用单一加权总分掩盖关键链路缺失。

### 6.3 视觉与数据判定

功能遗漏、交互不可达、内容遮挡、错误的操作反馈和关键弹层偏差优先修复；低影响差异也必须登记，不能静默忽略。视觉容差应基于稳定截图和差异区域校准，未经评审不写任意像素百分比为“通过”。

实时数据用同一绝对时间范围、相同筛选和排序对照；固定响应测试与真实接口测试分开标识。任何 mask 都须注明原因，不能遮蔽核心结果与交互区域来获得通过。
