# 弹出层专项迁移与验收

此清单补充已批准迁移计划。主页面通过不自动代表弹出层通过；每个入口的浮层状态独立登记。当前上下文/实时日志已修复首批布局问题，详见 analyze-info/reports/p9/context-overlay-style.md，其他项仍待逐一核验。

## 每个弹出入口必须执行

1. 沿V2调用链记录触发器、组件、props、插槽、事件、关闭方式、挂载目标、销毁时机和后端副作用。区分弹窗、抽屉、全屏面板、Popover/Tippy、下拉菜单、日期面板和嵌套确认框。
2. 在V2展开实际入口，记录初次打开、加载完成、空态、错误、展开、滚动后、校验失败、取消、确认及重新打开；确认前先核对是否属于写入，禁止修改已有资源。
3. 在同数据及视口的V3复现，核对Teleport后的独立根类。主页面祖先选择器、scoped深度选择器不能默认覆盖body挂载内容。业务样式限定所属overlayClassName/dialogClassName等公开属性，不全局修改所有.t-dialog/.t-popup。
4. 核对header/footer是否需要占位、宽高和min-height、内外边距、字号、图标、边框、圆角、控件默认宽度、触发器宽度与菜单宽度、虚拟列表及内外滚动归属。
5. 验证1440×900与1280×800。截图时等待实际加载遮罩和有限动画完成；同时保存实际innerWidth/innerHeight，未生效的尺寸覆盖不得计通过。检查按钮裁切、水平溢出、双滚动条、底部操作区及关闭按钮。
6. 嵌套浮层单独打开，检查z-index、elementFromPoint命中、遮罩、可点击区、翻转定位、滚动跟随和下拉选项。不得通过无限提高全局z-index掩盖父子层级。
7. 验证焦点进入、Tab/Shift+Tab、Enter、Escape、外部点击、关闭图标、取消、父级互斥和同一对象再次打开。与V2保持相同草稿保留/清除，不自拟业务规则。
8. 关闭后检查事件仅触发一次、定时器/监听/轮询/拖拽与Tippy实例清理；延迟请求和关闭动画不得影响新打开实例。
9. 控件替换时逐项映射原参数、事件payload、插槽、校验、loading、禁用、搜索、clear/paste及公共实例方法。禁止保留旧DOM选择器却声称新组件行为已实现。
10. 保存源码摘要、操作契约、场景数据、截图、断言、请求结果及剩余差异。分别登记业务和视觉结论；截图/固定数据/异常分支缺失时保持待验证。

## 执行顺序

- 检索：上下文/实时日志及其字段设置、筛选、高亮跳转、代码模式、分栏拖动；详情侧栏、字段值操作和排序/字段配置。
- 工具栏：索引、历史、时间与日历、自动刷新、场景条件、分享、收藏和AI结果面板。时间组件继续使用@blueking/date-picker的Vue3版本。
- 管理：采集新增/编辑抽屉、步骤确认、路径/目标选择、标签、启停、清洗/脱敏/提取/归档/ES及授权弹窗。
- 集成：V1 iframe、APM/Trace宿主内的全屏和嵌套浮层，核对父窗口尺寸、滚动、层级和关闭语义。

以上为实施顺序，不能据此勾选全业务通过。每项按V2源码及实际状态完成后再登记。
