# V3 官方时间组件弹层修复（2026-11-03）

本批解决 R02 的“时间弹层空白”和嵌套选择器交互缺失；R02 从 BLOCKED 更新为 IMPLEMENTING，业务与视觉整体仍未签收。参考业务为 16176，空间 bkcc__5000140，业务 5000140。

## 修复依据

V2 功能依据为 `packages/web-v2/src/components/time-range/time-range.tsx`。保留原时间范围、格式、时区、查询缓存和本地存储行为；没有重写日期计算、预设、日历或自然日期规则。

组件继续使用已安装的 `@blueking/date-picker@4.0.0-beta.9` Vue3 入口。原 V3 将其放在兼容运行时下渲染，tippy 移动懒加载节点后发生脱离；只隔离 SDK 根节点时，内部 TDesign 适配层仍处于另一 Vue 运行时，标签页生命周期也会失败。

进一步复核 SDK 源码发现：

- Tab 使用 active/update:active 和 Tab.TabPanel.name，不能直接等同于 TDesign Tabs。
- Select 使用 Option.id/name、Group、filterOption 和 hidePopover，不能仅替换导出名称。
- 日期面板通过 `.__bk-date-picker-popper__` 判断嵌套弹层归属。单位下拉如果直接挂载到 body 而未建立边界，点击选项就会提前关闭主面板。
- Input 的 prefix 承担“的最近／未来”文案，不能当作图标属性直接丢弃。

## 实现边界与文件

- `src/shared/ui/time-range/time-range.tsx`：保留应用状态、缓存和业务事件；渲染一个 DOM 宿主，挂载官方组件；属性变化同步到子应用，停用时隐藏，卸载时销毁。
- `src/platform/sdk/date-picker/contract.ts`：描述跨边界的值、事件、显示/隐藏、更新及销毁接口。日期值保留 SDK 的字符串、数值或 Dayjs 类型，绝对时间不会被强行转换成字符串。
- `src/platform/sdk/date-picker/native-entry.ts`：仅持有 SDK 展示状态，使用官方 DatePicker；不持有业务 store，不跨运行时传递 VNode。
- `src/platform/sdk/date-picker/virtual.d.ts`：虚拟模块的类型声明与真实实现关联。
- `tools/date-picker-island.ts`：构建完整原生 Vue3 SDK 依赖图，包含 TDesign 与第三方协议适配层。构建时检查不得混入 @vue/compat；开发与主应用、APM、Trace 采用同一机制。
- `src/platform/compat/tdesign/bkui-vue.ts`：仅面向第三方 SDK 的 Tab、Select、分组、搜索、弹层及 Input 协议转换。业务组件继续直接使用 TDesign。
- `tools/third-party-boundary-audit.mjs`：只允许指定 native-entry 导入 SDK；其他业务直接导入与 Vue2 入口仍被检查拒绝。
- `tools/verify-monitor-build.mjs`：将新构建插件纳入摘要，防止宿主产物与配置失配。

没有修改 node_modules、SDK 压缩文件，也没有全局切换兼容模式。

这是兼容宿主存续期间的局部边界。完整子图的独立产物约 621 KB，gzip 约 193 KB，存在运行时及控件代码重复的成本。待主应用移除兼容运行时后，应将 TimeRange 改为直接渲染官方 Vue3 组件，再删除虚拟模块与子应用桥接；仍保留业务事件和 SDK 适配契约测试。
