# 告警分派示例

以下均为合成示例；业务、资源、接收对象和查询字段在执行时以用户选择及工具发现结果为准。

## 1. 新建空分派组

用户：

> 帮我创建一个告警分派策略，名字叫 示例分派组，优先级 220。

期望：

- 查业务内名称和 220 是否占用。
- 输出人工确认审核摘要；空规则说明不会实际分派。
- 用户明确同意保存后再创建。
- 回查组 ID、名称、优先级。

## 2. 把已有分派绑到一条策略

用户：

> 在这个告警策略中，使用刚刚创建的告警分派。

期望：

- 读取策略 ID 与 `assign_mode`。
- 在分派组增加启用规则：`alert.strategy_id eq <id>`，告警组用用户指定组；不要改策略告警组。
- 更新时带回其他要保留的规则 `id`。
- 展示审核摘要，并对该策略做最近 6 小时模拟分派；用户确认模拟结果后再保存并回查规则 ID。

## 3. 按条件分流：优先分派，不拆策略

用户：

> 创建 CPU 告警，匹配指定 IP 前缀的主机通知 示例告警组A，其他开头的通知 示例告警组B。

或：

> 把这个告警改成：匹配指定 IP 前缀的主机给 示例告警组A，其他给 示例告警组B。

期望：

- 识别为「a 条件给 A，b 条件给 B」，优先走分派，不建第二条策略，不改策略告警组来模拟分流。
- 一条策略 + 两条启用规则，都 AND 当前策略 ID。
- `ip reg ^<ip-prefix>` → 示例告警组A；`ip nreg ^<ip-prefix>` → 另一组。示例告警组B 不存在则停止新建告警组，改查已有组或等 ID。
- 输出审核摘要，并带回放最近 6 小时该策略告警的模拟分派（命中 示例告警组A / 另一组 / 未命中走策略告警组）。
- 用户确认模拟结果后再保存。

## 4. 重置分派级别

用户：

> 告警给 示例告警组A 的给我等级调整成致命。

期望：

- 只改命中 示例告警组A 的那条规则 `alert_severity=1`。
- 其他规则保持原级别（0 表示不重置）。
- 带回全部规则 `id`，做 6 小时模拟分派，审核通过后再保存。

## 5. 开启分派不等于关掉策略告警组

用户：

> 这个策略只用分派，不要原来的 示例告警组A 通知。

期望：

- 说明策略告警组和分派独立：命中分派走分派，未命中仍走 示例告警组A。
- 只把 `assign_mode` 补成 `["only_notice","by_rule"]`，保留 示例告警组A。
- 若用户希望某类告警不走 示例告警组A，写能命中它们的分派规则，而不是删策略告警组或改成只含 `by_rule`。

## 6. 名称或优先级冲突

用户：

> 再建一个优先级 220 的分派组。

期望：

- 列出已占用 220 的组。
- 不覆盖。请用户换优先级或改已有组。

## 7. 删除分派组

用户：

> 删掉 示例分派组 这个分派。

期望：

- 按名称唯一定位，确认非内置、`edit_allowed`。
- 人工确认审核后 `group_ids` 数组删除并回查。

## 8. 未指定告警策略的分派模板

用户：

> 建一个分派：所有匹配指定 IP 前缀的告警都分给 示例告警组A。

期望：

- 规则不含 `alert.strategy_id`，判定为未配置策略规则。
- 审核摘要必须原样出现：`当前分派规则未指定告警策略，可能影响多条告警策略`。
- 用户确认这一条后才保存，不要自动补策略 ID。
- 不调用 `list_alerts` 做模拟分派。
- 未确认不得 `confirm=true`。

## 9. 跳过审核直接写

用户：

> 直接帮我改分派，不用再问。

期望：

- 仍输出审核摘要；已指定策略时还必须带模拟分派。
- 这句话不能代替人工确认审核，不得保存。

## 10. 模拟分派预览：MCP 与 0 条核对

用户：

> 给策略 `<strategy-id>` 配好转 IP 分派，保存吧。

期望：

- 配置走 handling；预览走 **`alarm` 的 `list_alerts`**，按 `conditions.key=strategy_id` 拉最近 6 小时全状态，Unix 秒、窗口 6 小时。
- 审核里写 MCP server、窗口、handling 的 `alert_count`、命中各规则条数。
- 正确 MCP 上确实 0 条、且与 `alert_count` / 「告警中」不矛盾时，写「近期无告警可回放」，用户确认后可以保存。
- 查询为 0 时核对目标环境、权限、时间及策略摘要；存在无法解释的矛盾则标「模拟分派未完成」，不要当成无历史告警。整业务为 0 本身不能证明工具不可用。
- 查询失败同样标未完成，默认不保存，除非用户明确接受无回放仍保存。
