# 告警风暴与维度预览

## 目标与边界

在指标告警写入前，用历史指标执行范围预览，回答：

1. 当前目标范围包含多少时序和目标。
2. 历史窗口内每个周期有多少维度组合命中阈值。
3. 按检测窗口回放后，可能生成多少告警实例和状态切换。
4. 配置的聚合维度是否带来组合基数激增。

结论统一称为“历史回放预估”。它不能预测未来数据，也不能完全复刻告警引擎的去重、收敛、延迟、缺失点和状态持久化，不得表述为精确告警数。

当前主路径适用于能转换为有效 PromQL 的时序指标策略。日志关键字策略继续使用 `search_logs` 的命中量做高频风险提示，不把日志条数直接等同于告警实例数。

## 输入

执行前必须明确：

- `bk_biz_id`
- 有效 PromQL 或可转换为 PromQL 的指标查询
- 目标过滤条件
- `agg_interval`
- `agg_dimension`
- 阈值比较符和阈值
- `trigger_count`
- `check_window`
- `recovery_window`

缺少任一检测语义时先补齐草稿，不执行伪回放。

`<scope_promql>` 表示应用业务、目标过滤、聚合方法和有效聚合维度后的策略查询，不是忽略过滤条件的裸指标。比较符映射为：`gt -> >`、`gte -> >=`、`lt -> <`、`lte -> <=`、`eq -> ==`、`neq -> !=`。

## 两阶段查询

### 第一阶段：最近 1 小时快速扫描

调用 `execute_range_query`，时间戳必须动态计算，`step` 与策略 `agg_interval` 一致。

至少执行：

1. 总序列趋势：

   ```promql
   count(<scope_promql>)
   ```

2. 阈值命中序列趋势：

   ```promql
   count(<scope_promql> <comparison> <threshold>)
   ```

3. 每个配置维度的基数：

   ```promql
   count(count by (<dimension>) (<scope_promql>))
   ```

4. 完整维度组合基数：

   ```promql
   count(count by (<dimension_1>, <dimension_2>) (<scope_promql>))
   ```

无 `agg_dimension` 时按策略实际目标身份维度统计；主机优先使用策略中的目标维度，不自行把 `hostname`、`ip` 等展示字段加入告警维度。

### 第二阶段：最近 24 小时扩展扫描

第一阶段为中风险或高风险时自动扩展到最近 24 小时。单次查询跨度不得超过 86400 秒。

扩展扫描复用同一 PromQL、过滤条件和步长，比较：

- 总序列数的最小值、平均值、峰值。
- 阈值命中数的最小值、平均值、P95 近似值和峰值。
- 维度组合基数的最小值与峰值。
- 高风险是否只出现在短时尖峰。

无法扩展时保留 1 小时结论，并标记“24 小时扩展未验证”。

## 查询成本保护

- 先执行聚合计数，再决定是否拉取按维度聚合的明细序列。
- 总序列峰值超过 1000 时，不默认拉取全部原始物理序列；先按策略有效 `agg_dimension` 聚合。
- 维度组合峰值超过 1000 时，可直接判定维度高风险，不为精确回放下载全部组合。
- PromQL 失败、超时或结果被截断时停止精确回放，输出已取得的聚合证据和“预估不完整”。
- 不为了预览扩大用户原本的业务、目标或时间范围。

## 历史回放口径

### 告警实例身份

一个候选告警实例对应一个实际聚合维度组合。相同目标的别名字段不重复计数；例如 `bk_host_id` 与同一主机的 `ip` 同时存在但未配置为聚合维度时，不增加实例数。

### 周期异常

对每个组合、每个 `agg_interval` 周期计算阈值真假：

```text
abnormal[t] = compare(value[t], method, threshold)
```

缺失点按策略 `no_data_config` 单独处理；未启用无数据告警时，不把缺失点当作阈值异常。

### 触发回放

在连续 `check_window` 个周期中，异常周期数达到 `trigger_count` 时，该组合进入“满足触发条件”状态。

```text
qualifies[t] = sum(abnormal[t-check_window+1..t]) >= trigger_count
```

“5 周期满足 1 次”必须解释为 `check_window=5`、`trigger_count=1`。

### 恢复与状态切换

- 正常到满足触发条件：计一次预计新告警状态切换。
- 告警状态连续满足 `recovery_window` 个恢复周期：计一次预计恢复。
- 已处于告警状态时连续异常不重复计为新告警实例。

若 MCP 结果规模不允许逐组合回放，使用以下范围替代：

- 下界：历史窗口内至少一次满足条件的唯一组合数。
- 上界：各周期满足条件组合数之和。
- 峰值并发：单周期满足条件组合数峰值。

## 维度爆炸检测

需要区分：

- 目标范围大：目标身份数量本身很大，例如全量 500 台主机。
- 维度爆炸：额外维度使同一目标拆分成大量组合，例如主机 × 进程 × 端口。

对每个配置维度计算：

- 单维度基数 `cardinality(d)`
- 完整组合数 `combination_count`
- 去掉该维度后的组合数 `combination_without(d)`
- 维度贡献倍数：

  ```text
  multiplier(d) = combination_count / max(1, combination_without(d))
  ```

`bk_host_id` 与 `ip` 等一一映射维度通常不会产生高贡献倍数；独立变化的设备、进程、接口、容器、URL 等维度需重点检查。

## 默认风险阈值

阈值是 Skill 默认值，应在输出中注明可调整。任一条件命中即取最高风险等级。

### 高风险

- 单周期阈值命中峰值或回放触发组合数 `>= 100`
- 完整维度组合峰值 `>= 1000`
- 任一维度贡献倍数 `>= 10`
- 命中率 `>= 50%` 且目标或组合总数 `>= 50`
- 预计新告警状态切换 `>= 200/小时`
- 查询规模过大，无法完成明细回放

### 中风险

- 单周期阈值命中峰值或回放触发组合数为 `20–99`
- 完整维度组合峰值为 `200–999`
- 任一维度贡献倍数为 `3–9.99`
- 预计新告警状态切换为 `50–199/小时`
- 1 小时结果存在明显尖峰，需扩展到 24 小时确认

### 低风险

未命中中风险或高风险条件，且查询、维度和回放数据完整。

## 门禁

- 低风险：展示预览后进入正常创建确认。
- 中风险：完成 24 小时扩展预览，要求用户针对风险结果二次确认。
- 高风险：默认停止创建，给出收窄目标、提高阈值、增加触发次数、减少维度或先停用创建等建议。
- 高风险覆盖：只有用户已看到完整证据并明确要求强制创建时才允许继续；写后输出必须保留风险提示。
- 预估不完整：至少按中风险处理；若总序列或组合规模已超过高风险阈值，则按高风险处理。

## 输出

```text
历史回放预估：通过/高风险/未完整验证
窗口：最近 1 小时；已扩展/未扩展到最近 24 小时

范围：
- 目标/总序列：<min/avg/max>
- 阈值命中：<avg/p95/max> 每周期
- 命中率峰值：<percent>

告警实例：
- 唯一触发维度：<count 或 lower-upper>
- 峰值并发：<count>
- 预计新告警状态切换：<count/hour 或 lower-upper>

维度：
- <dimension>: 基数 <n>，贡献倍数 <x>
- 完整组合：<count>
- 主要放大维度：<dimension 或无>

风险：低/中/高
门禁：正常确认/二次确认/默认停止
限制：历史数据不代表未来；未模拟通知、收敛和真实告警引擎。
```
