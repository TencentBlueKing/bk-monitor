# 策略草稿与输出规范

## 创建草稿

写入前至少展示：

```text
业务：<名称或 bk_biz_id>
策略名称：<name>
场景：<scenario>
状态：创建后启用/停用

监控项：
- 数据源：<data_source_label>/<data_type_label>
- 指标策略：结果表 <result_table_id> / 指标 <metric_field>
- 日志策略：采集项 <collector_name> / 索引集 <index_set_id> / 检索语句 <query_string>
- 聚合：<agg_method> / <agg_interval>s
- 维度：<agg_dimension>
- 目标：<全部目标或具体范围>

检测规则：
- 条件：<指标> <比较符> <阈值><单位>
- 触发：<check_window> 个周期满足 <trigger_count> 次
- 恢复：连续 <recovery_window> 个周期
- 级别：致命/预警/提醒
- 无数据告警：启用/停用

通知：
- 告警组：<名称和 ID>
- 接收人：<用户/角色>
- 渠道与时段：<配置摘要>
- 消息模板：<默认或自定义摘要>
- 处理套餐：<名称和 ID，若有>
- 分派：<未开启 / 已开启：符合规则走分派，不符合走上方告警组>
- 分派规则：<无 / 分派组名称和 ID / 条件、分派告警组、级别重置>

查重：<无重复或候选策略>
验证：<L1/L2/L3/L4 结果>
风险：<阈值、范围、告警量、维度组合、通知、能力限制>
```

指标策略必须增加历史回放预览：

```text
预估窗口：最近 1 小时；中/高风险时扩展到最近 24 小时
目标/总序列：<min/avg/max>
阈值命中：<avg/p95/max> 每周期；峰值命中率 <percent>
预计告警实例：唯一触发维度 <count 或 lower-upper>；峰值并发 <count>
预计状态切换：<count/hour 或 lower-upper>
维度组合：<combination_count>
维度基数：<dimension=count, multiplier=x>
主要放大维度：<dimension 或无>
风险等级：低/中/高/预估不完整
门禁：正常确认/二次确认/默认停止/用户明确覆盖
限制：历史数据不代表未来，未模拟真实告警引擎和通知收敛
```

风险数值必须附带查询窗口、PromQL/查询摘要和计算口径。中风险或高风险未完成 24 小时扩展时，不得降为低风险。

日志关键字草稿还需展示：

```text
数据验证窗口：<start_time> -> <end_time>
命中总量：<total>
样例摘要：<时间、来源、脱敏后的日志摘要>
计数条件：每 <agg_interval>s 匹配数 <比较符> <阈值>
通知收敛：<是否启用、收敛窗口和重复通知间隔>
```

检索语句应原样展示，不把 `AND`、字段限定或排除条件改写成自然语言后再提交。命中量较高时，在风险中明确“创建并启用后可能持续触发”。

只有在上述信息足以确定生产行为后才能请求确认。

## 更新摘要

```text
对象：<策略/告警组/处理套餐/屏蔽名称和 ID>
业务：<bk_biz_id>

变更：
- <字段>：<原值> -> <新值>

保持不变：
- <关键嵌套配置摘要>

影响范围：
- <引用策略数量和候选；无法查询时明确说明>

验证与限制：
- <配置验证>
- <数据验证和历史回放预估>
- <未执行的真实触发与通知验证>
```

## 写后回查

写入成功后，输出必须基于回查对象：

- 资源 ID、名称、业务 ID。
- 实际保存的指标、阈值、触发和恢复配置。
- 日志策略的实际 `index_set_id`、`query_string`、`agg_interval` 和物理结果表。
- 实际告警组、接收人、处理套餐和消息模板。
- 实际分派组 ID、规则 ID、匹配条件和 `alert_severity`。
- 实际 `notice.options.assign_mode`。
- 实际启停或屏蔽状态。
- 写入时间或更新时间（返回时）。
- 草稿与实际配置是否一致。
- 创建前历史回放风险和用户是否执行风险覆盖。
- 未执行的验证项。

若写接口成功但回查不一致，列出差异并停止继续修改，除非用户再次确认。

## 候选输出

多命中时只展示帮助用户区分的字段：

- ID、名称、业务。
- 场景、指标或类型。
- 启停/生效状态。
- 更新时间。

不要输出大量无关聚合元数据，也不要自动选择。

## 失败输出

```text
结果：未完成
失败步骤：<查询/创建/更新/回查>
错误：<后端原始错误的简明说明>
已确认未发生：<未写入/未覆盖/未重复提交>
建议：<补参数、改用完整对象、人工操作或等待 API 能力>
```
