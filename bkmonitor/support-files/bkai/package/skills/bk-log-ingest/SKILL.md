# 日志接入

## 环境与依赖

目标监控网关的 `log-collector`；仅主机目标定位额外需要同一环境 CMDB MCP 的四个工具，见主机目标定位参考。

先确认目标环境和 `bk_biz_id`，再发现该环境已授权的 MCP 工具并读取实时 schema。下文的 Server 后缀不是可直接调用的完整名称；无法唯一定位或缺少依赖时停止相应步骤，不跨环境回退。宿主提供认证入口时使用该入口完成认证，不在 Skill 中保存凭据。

采集读写使用目标监控网关的 `log-collector`。主机目标定位使用同一环境 CMDB MCP 的四个工具，见 [references/host-target-resolve.md](references/host-target-resolve.md)。查日志明细走 `bk-log-query`；告警策略配置不属于本 Skill，交给目标环境提供的相应能力。

## 1. 先定接入类型

当前只支持四种：

| 用户说法 | 接入类型 |
| --- | --- |
| 主机、Linux、机器、IP、拓扑、动态分组 | 主机采集 |
| 容器文件、容器内路径、容器日志文件 | 容器日志采集 |
| 标准输出、stdout、容器 stdout | 容器标准输出采集 |
| Windows Event、winevent、Windows 事件 | Windows Event 采集 |

用户已指定类型：按该类型继续。没指定：列出上面四种并询问，不要默认成主机。

Kafka、Redis、Syslog、自定义上报：说明当前不支持，停止。

主机目标见 [references/host.md](references/host.md)；用户只给 IP/名称，出表单前用 CMDB 定位，流程见 [references/host-target-resolve.md](references/host-target-resolve.md)。容器日志范围见 [references/container.md](references/container.md)。容器标准输出确认表单已有（范围圈选、无路径）；其它特有字段尚未沉淀。Windows Event 尚未沉淀：类型认出来之后缺什么问什么。

## 2. 补齐配置，再出确认表单页

缺必填就问。能默认的不要反复问。出表单前先解析**存储集群名称**（系统选定的真实名称，禁止写「公共集群」）。主机采集还要先按 [host-target-resolve.md](references/host-target-resolve.md) 用名称/IP 定位成功。补齐后必须先给**确认采集配置表单页**，用户确认前禁止下发。

三种已沉淀类型各用对应表单，不要混用，也不要用纯文本清单代替：

| 接入类型 | 表单页 |
| --- | --- |
| 主机采集 | 配置表单 + **采集目标**表 + **日志路径**表 |
| 容器日志采集 | 配置表单 + **采集配置范围**竖表（一条 config 一张，Container / Node，含路径行） |
| 容器标准输出采集 | 配置表单 + **采集配置范围**竖表（一条 config 一张，仅 Container，无路径行） |

表单底部让用户选其一：

- **直接下发**：立即创建采集，清洗为直接入库
- **下发并清洗**：立即创建采集（此时已在下发状态），再配清洗

用户改表单内容时更新表单，再确认。用户选定后立刻调用创建接口，不要等清洗配完。

输出格式见 [references/confirm-forms.md](references/confirm-forms.md)。MCP 步骤见 [references/mcp-workflow.md](references/mcp-workflow.md)。

## 3. 可以做 / 不能做

**可以做**

- 四种接入类型的新建
- 主机、容器日志按下表共用默认值和必填；容器日志只把采集目标换成范围圈选
- 主机目标按 IP、主机名、模块名、集群名、动态分组名圈选；ID 由 CMDB 内部解析
- 用户指定存储集群则用指定集群；不指定则由系统选定，确认表展示该集群名称
- 过期时间、副本、分片按默认值或用户修改值提交
- 确认后立即下发；选「下发并清洗」时采集已在下发状态，再配清洗

**不能做**

- 未确认采集配置表单页就调用写接口
- 调整上报链路
- 创建完成后修改采集范围
- 段日志没有行首正则就提交
- 把未支持的接入类型做成上述四种之一
- 向用户要主机 / 模块 / 分组 ID；云区域默认成 0
- 把动态拓扑或动态分组展开成 IP 再当静态主机提交
- 主机目标尚未在本业务定位成功就出确认表或创建采集

## 4. 主机与容器日志：默认值与必填

存储、清洗、名称、路径、字符集、行/段日志、采集范围、上报链路：**主机和容器日志相同**。差别只有采集目标。

| 项 | 规则 |
| --- | --- |
| 采集名称 | 用户输入即为采集名称；可按意图改成更清楚的名字，改了要在确认表单里展示 |
| 数据名 | 默认由采集名称转成合法英文，与采集名称的英文形态一致 |
| 日志类型 | 默认行日志；用户明确要段日志才切换。段日志必须有行首正则 |
| 采集目标 | **主机**：用户只给 IP、主机名、模块名、集群名、动态分组名，不要要 ID。出表单前按 [host-target-resolve.md](references/host-target-resolve.md) 在本业务定位；确认表「采集目标」只填名称/IP。**容器日志**：不用 IP，按配置圈定 Container / Node 范围，写在「采集配置范围」竖表（一条 config 一张） |
| 日志路径 | 必填，可多个 |
| 字符集 | 默认 UTF-8 |
| 采集范围 | 默认仅采集下发后的日志；创建完成后不可改 |
| 上报链路 | 用户不可调，不要问、不要改 |
| 存储 | 用户指定则用指定集群；否则系统选定。确认表填集群**名称**（`display_name`，没有则 `cluster_name`），禁止写「公共集群」 |
| 过期时间 | 默认 3 天，用户可改 |
| 副本 | 默认 0 |
| 分片 | 默认 3 |

容器日志、容器标准输出的确认表单必须把目标写成**采集配置范围**竖表（配置项 / 内容），禁止横表。一条 `configs` 一张表，多条就多张并编号。不要列 IP。容器日志可含 Container / Node；容器标准输出只圈 Container、不要 Node。范围说不清就问，不要默认成全集群全量。

## 5. 下发并清洗

仅当用户在确认表单选择「下发并清洗」。选定后先创建采集，保证已在下发状态，再配清洗。

必须先选清洗模式：**json / 分隔符 / 正则**。没选就问，不要默认一种模式。

样例优先用本采集已上报的日志；确认没有日志，才让用户手动贴。不要在下发前向用户要样例。

配完后先返回**字段清洗结果页**（清洗设置表单 + **字段列表**表格），确认后再写清洗接口。三种接入类型共用这一页。字段列表**禁止出现「别名」列**；与内置字段冲突时，该列标题改为 **字段冲突【调整为】**。

清洗默认值（用户没说就用）：

| 项 | 默认 |
| --- | --- |
| 原始日志 | 保留 |
| 指定日志时间 | 日志上报时间（不要擅自指定某个字段当时间） |
| 失败日志 | 保留 |

字段约定、模式参数见 [references/clean.md](references/clean.md)。
