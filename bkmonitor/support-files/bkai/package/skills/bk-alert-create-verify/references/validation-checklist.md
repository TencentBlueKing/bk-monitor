# 告警验证检查清单

## 验证结论分级

每项只允许输出 `通过`、`失败`、`未验证`，并附证据。

### L1 配置验证（必做）

- 业务 ID 明确且唯一。
- 策略名称、场景、数据源完整；指标策略的结果表/指标字段或日志策略的索引集/检索语句完整。
- 聚合方式、聚合周期和维度结构合法。
- 检测算法、比较符、阈值、触发次数、检测窗口完整。
- 恢复窗口和告警级别明确。
- 监控目标符合用户范围；空目标已明确表示业务全部目标。
- 已查询同名、同指标或相似策略。
- 告警组存在，至少有一个有效接收人和通知方式。
- 用户指定分派或条件分流时：目标告警组均已解析；分派组名称/优先级不冲突；`assign_mode` 为 `only_notice + by_rule`；策略告警组未被清空或替换；已完成人工确认审核。
- 分派规则未含 `alert.strategy_id` 时，已展示「当前分派规则未指定告警策略，可能影响多条告警策略」并获得确认；未做模拟分派。
- 已指定策略的分派已完成最近 6 小时模拟分派，用户已确认结果。
- 条件分流未被拆成多条策略。
- 处理套餐存在，类型与用户诉求相符。
- 写操作已展示草稿或差异并取得明确确认。

日志关键字专项检查：

- `data_source_label=bk_log_search`、`data_type_label=log`。
- `index_set_id` 来自 `list_index_sets` 的唯一匹配，不根据采集项名称猜测。
- 已用 `get_index_set_fields` 确认检索字段，用完全相同的 `query_string` 调用 `search_logs`。
- `result_table_id`、`time_field` 和聚合字段来自可靠元数据或同索引已有策略，不拼接臆造。
- `items` 中的计数阈值与 `detects.trigger_config` 语义一致；例如“5 周期满足 1 次”对应 `check_window=5`、`count=1`。
- 创建 payload 使用完整 `items/detects/notice`，未携带从其他策略复制的内部 ID。
- 更新 payload 保留本策略内部 ID，并使用最新 `config_version`。

### L2 数据验证（按能力执行）

- 指标/日志/事件来源可查询。
- 最近窗口有数据。
- 单位、维度和返回序列符合预期。
- 无明显采集延迟、缺失或目标范围为空。
- 日志查询返回总量、样例时间和目标检索语义一致；高命中量已提示告警风暴风险。

当前没有数据查询 MCP 时，以上项目全部标记 `未验证`，不得用策略创建成功替代。

### L3 历史回放预估（指标策略按能力执行）

- 预览 PromQL 与策略的业务、目标过滤、聚合方式、维度和阈值一致。
- 快速扫描使用最近 1 小时，`step` 与 `agg_interval` 一致。
- 中风险或高风险已扩展到最近 24 小时；扩展失败时已标记预估不完整。
- 已输出总序列数、阈值命中数、唯一触发维度、峰值并发和预计状态切换范围。
- 已统计每个聚合维度基数、完整组合数和主要放大维度。
- 已区分目标范围大与额外维度造成的组合爆炸。
- 输出使用“历史回放预估”，未声称真实告警引擎已试算。

无法完成 PromQL 查询时标记 `未验证` 或 `预估不完整`，并按风险门禁处理。

### L4 真实触发与通知验证（当前不可执行）

- 历史窗口试算是否命中。
- 模拟事件是否触发策略。
- 企业微信、邮件、短信、语音等通知是否真实送达。
- HTTP 回调是否连通且返回成功。

当前 API/MCP 未提供这些能力，统一标记 `未验证`。不要输出 `notice_verification_status=passed` 或类似暗示。

## 风险检查

- 阈值显著低于常用建议时，提示可能产生大量告警，但尊重用户明确选择。
- `trigger_count=1` 且窗口较大时，说明单点毛刺即可触发。
- 全部主机/全部容器目标会扩大告警量，创建前明确范围。
- 告警组为空、成员为空、通知时段不覆盖当前时间时，不允许声称通知配置完整。
- 公共告警组或处理套餐变更需提示引用策略影响。
- 同名或同指标策略已存在时，先建议复用或更新。
- 创建后立即启用会进入生产检测；用户只想验证配置时，优先建议先停用。
- 日志查询在最近窗口命中量高，且阈值为每周期 `> 0`、触发次数为 1 时，必须提示可能持续触发，并说明通知收敛配置。
- 指标单周期命中或回放触发维度达到 100、组合达到 1000、维度贡献倍数达到 10，或命中率达到 50% 且目标不少于 50 时，默认判高风险。
- 中风险必须二次确认；高风险默认停止创建，用户明确强制覆盖时保留风险证据。

## 更新能力检查

当前更新能力：

- 启停、标签、监控目标。
- 阈值算法、触发条件、恢复条件、无数据配置。
- 告警组、通知配置、处理套餐。
- 创建/更新后绑定告警分派组（`save_alarm_assign_group`）。开启分派只补 `by_rule`，保留策略告警组。
- 实时 schema 支持时，日志 `query_string/index_set_id`、PromQL/时序查询和聚合配置可通过完整策略更新。

以下字段不能通过简化局部字段直接更新：

- 指标或结果表。
- `query_configs`。
- `agg_dimension`。
- `agg_interval`。

上述字段如需修改，先读取完整策略，保留内部 ID 和未修改配置，按实时 schema 提交完整 `items` 与最新 `config_version`。实时 schema 不支持时不得提交到其他语义字段中，可选方案是：

1. 生成新策略草稿；
2. 用户确认后新建替代策略；
3. 在支持启停时停用旧策略；
4. 或提示用户在平台 UI 完成修改。

## 通知模板专项检查

- 更新前已读取最新 `notice`。
- 只修改用户指定的 signal：异常、恢复、无数据等。
- 保留通知间隔、轮询、收敛、图表、语音模式和其他模板。
- 使用平台支持的变量，例如 `{{content.content}}`。
- 写后回查模板文本与 signal。

## 验证输出模板

```text
配置验证：通过/失败
- 证据：...

数据验证：通过/失败/未验证
- 证据或限制：...

历史回放预估：低风险/中风险/高风险/未完整验证
- 窗口、目标/序列范围、阈值命中、预计告警实例和维度组合：...

真实触发与通知：未验证
- 原因：当前无真实告警引擎试算和模拟通知 MCP/API
```
