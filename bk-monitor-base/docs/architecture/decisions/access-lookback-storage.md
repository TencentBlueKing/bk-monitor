# Access 回看配置的存储方式

## 背景

回看周期是监控项自身的配置，需要经过策略创建、更新、读取和缓存进入 Access。若接口将其作为普通字段、持久化却放在 meta 中，各条读写路径都需要额外转换，也容易遗漏公共包读取链路。

## 决策

使用 `ItemModel.access_lookback_periods` 独立可空整数列，`NULL` 表示未配置。Item 通过显式构造参数和公开属性传递该值，创建与更新沿用普通字段持久化流程，不使用 meta 存储。

保留未配置状态，而不把全局默认值写入数据库，使继承全局配置与显式覆盖保持可区分。序列化时省略未配置字段，避免给存量策略注入新配置。

## 影响

需要新增数据库迁移。监控旧表模式由监控仓库管理 `alarm_item_v2` 的结构；Base 独立建表模式由本仓库的 strategy 迁移管理。两种模式不能对同一张表重复执行迁移。

部署须先加列，再启用依赖新列的应用和 worker；回滚应用时保留新增列。具体升级顺序随变更在 PR 中说明。
